**共性结论（答辩可直接用）**：
1. 站前/落客区拥堵是全国性、被官方认定的问题（公安部 100 站专项整治是政策侧最硬背书）
2. 瓶颈集中在**匝道与落客车道**（2 车道匝道汇流）和**落客位利用不均**；量化参照：广州南效率缺口 ~27%、北京南"20 分钟→1.5 分钟"是改善幅度参照
3. **现有措施全部是"空间分流 + 时间/价格约束 + 叫号匹配"三类，没有任何一例"按路段容量×分钟时段预约"**——HubFlow 的差异化空档

**学术量化参照（方法学）**：
- 秦绍清等《基于MFD的高铁站周围路网诱导-控制方法》（交通运输研究 2021,7(6)）：以西安北站为例，诱导-控制后平均车速 +25.39%/4.61%（vs 无控制/单一边界控制），延误 -28.22%/10.05%——**与本项目场景最接近的中文文献**
- 《铁路客运枢纽车道边落客长度指标研究》（城市道桥与防洪 2023）：车均落客长度 9.5~12.5m
- 《客运枢纽送站坪出租车车道通行能力研究》(2022)：**落客区长度增加 300% 时流出流量仅 +11.2%**——支持"需求侧管控"而非"纯扩容"的论证
- 可信度：中（著录为搜索摘要，建议答辩前抽 2 篇 CNKI 核实）

## 2. 竞品对标：导航 App 与平台现状

### 2.1 三层能力现状

| 层 | 代表 | 能力 |
|---|---|---|
| 场外路况推荐 | 高德（广州南已协调三家导航） | "优先推荐车流较少区域落客" |
| 场内车位级引导 | 高德枢纽方案（杭州东全国首个；全国 50+ 场站；浦东机场司乘汇合 -60%） | 通道号+车位号推送、AR 导航 |
| 人车匹配叫号 | 深圳北"一码出行"、合肥南"车牌后四位预约"、上海虹桥调度平台（应答<15min、-30%） | 扫码叫号、动态车位、电子围栏 |

**关键判断：三者均不触及"对某条路段在某时段允许多少车驶入"（准入配额）这一层。**

### 2.2 现实中的"预约通行"最接近实践

- **深圳片区级预约通行**（全国首个，2018 起）：大鹏/梅沙每日 4 万配额、时段 0-12/12-18/18-24，未约罚 300 记 1 分，出租网约豁免——**粒度"片区×半天"，与"路段×1分钟"差 2-3 个数量级**
- 学术配额研究：最佳预约总量 ≈ 通行能力的 **0.79~0.89**（奖惩机制下取 0.85）

### 2.3 查新结论（★核心，可直接作为创新性主张）

> **未检索到「按路段 × 1 分钟时段为每辆车预约路段容量」的直接先例，更未检索到「时段容量预约 + 不伤害前车（新增延误≤30s）硬约束 + 前车再疏导」的组合先例。**

最接近先例（答辩时列出以示严谨）：

| 先例 | 机制 | 与 HubFlow 差异 |
|---|---|---|
| 专利 CN113990072B（2023 授权，个人） | 路段最大通行能力→进入车辆数上下限→审批+预约通道开合 | 时段粒度粗、无下游保护约束、无再疏导 |
| 专利 CN104200649B（2016，沈阳工大） | 路线当有限资源，`C=C_basic×γ天气×γ车速×γ路况`，按时段审批、超额延后/改线 | 无分钟级、无车辆级、无"不伤害"约束 |
| Su/Park/Son 2017 (VEHITS) | 高速切路段、时间离散区间，预约槽=「路段×3分钟」 | 离线系统最优、高速主线、无逐车防伤害 |
| Liu 2013 token 预约 / Lamotte 2017 / Menelaou 2015 | token=路段长×临界密度；容量约束预约；事前路径预约(SUMO) | 控制周期远大于 1 分钟 |
| 深圳预约通行 / BCR（TR-B 2023） | 瓶颈/片区配额+"预约+限行" | 粒度"瓶颈×日/月" |

建议表述：「经公开文献与专利检索，'1 分钟级路段容量预约'在车辆级/路段级均无直接先例；HubFlow 的'时段容量预约+不伤害前车约束+前车再疏导'三件套组合未见于现有系统与专利。**首创面向枢纽站前路网的『路段×分钟时段容量预约+弱化扰动约束（新增延误≤30s）』疏导机制，并以数字孪生（SUMO）验证。**」
（正式查新建议补 CNKI/万方/CNIPA/Google Patents 全库，检索式「路段 AND 预约 AND 时段」「link-level reservation / slot allocation」）

## 3. 司机接受度与行为证据（含反面证据）

| 证据 | 数据 | 对 HubFlow 的含义 |
|---|---|---|
| 路径诱导服从率（国际综述） | 整体 ~65%，区间 50%~81%；近半驾驶者锚定熟路 | 服从率是设计变量而非默认值——仿真假设建议用中值 ~65% 起步，做 50~81% 扫描 |
| 服从率决定因素 | **指令式 > 描述式**信息；信息可靠/预测值 + 事后反馈提高服从；绕行节省越大越服从 | 建议卡设计：给明确落客点+预计排队（指令式），而非只报路况 |
| Metropia（美国激励诱导） | 3.1 万行程：积分激励显著正向；历史服从是当次最强预测；LA 试点 51% 改变路线、60%+ 愿改出发时间 | 激励设计有实证背书；"预约成功反馈"能强化服从 |
| **反面证据：场站排队博弈** | 大型枢纽是取消率最高场景（订单 6%）；排队单取消率 **15%** vs 未排队 8%；"扎针单"挤出队列；滴滴机场 AQS 使排队长度近翻倍而未提效；严格 FIFO 诱发挑单（EC'22 证明 Randomized FIFO 可解） | **必须设计反博弈条款**（预约爽约信用、防扎针）；"不伤害前车"对司机可感知的表述（"最多多等 0.5 个红灯"） |
| 正面案例 | 深圳北出租车积分预约：短途拒载率大降、鸣笛投诉归零 | 积分+短途优先+可感知反馈能扭转行为，但依赖物理围栏 |

## 4. 同类学术系统对标

| 系统 | 机制一句话 | 开源 | 与 HubFlow 关系 |
|---|---|---|---|
| 秦绍清 2021（西安北，MFD） | 子区最佳累积量 + **先诱导后边界限流** | 无 | 场景最接近；区域级、周期长——HubFlow 细化为路段×分钟 |
| Peng et al. 2025 (arXiv:2508.08617, UCDavis) | 上层区域流入率+超路径流，下层界线信控+路径选择 | **有：github.com/xypeng12/multi-region-routing-perimeter-control（SUMO）** | **可直接作复现/对标基线** |
| Lei et al. 2026 (Sci Rep) / T-ITS 2020 | 无模型自适应控制：边界放行比例+诱导比例协调 | 无 | 控制变量同构；"无模型+扰动补偿"思路可借鉴（场景数据少） |
| Sirmatel & Geroliminis 2018 / Fu et al. 2022 (T-ITS) | MPC 优化边界放行 + **路径诱导在缓冲区之间再分配排队** | 无 | **"边界排队再分配"≈ HubFlow"前车再疏导"的理论母体** |
| 工程实践：Perth CBD gating / Zurich | **soft gating（复用既有信号）胜出**；Perth 潜在 +39% 流量 | 无（Aimsun） | 为"不新建物理设施"的落地经济性提供类比论据 |
| Dresner & Stone 2008 (AIM) / Tachet 2016 (slot-based) | 车辆向路口申请**时空预留槽**，FCFS | 无正式仓 | 车辆级"预约+审批"原语源头；**AIM 的 starvation 缺陷正是"不伤害"约束要防的问题**；答辩需明确**区分交叉口级 vs 路段级** |
| Su 2017 / Li 2023 (TR-B) | 高速路段预约 / 瓶颈"预约+限行" | 无 | 路段级预约粒度最接近的文献；离线、无逐车约束 |

**差异化三句话**（学术对标用）：①控制粒度从"区域/交叉口"细化为"**路段×分钟**"；②引入"既有车辆不受害（≤30s）"硬约束，对应 AIM 的 starvation 与 gating 的"牺牲门控处延误"两个缺陷；③包含"前车再疏导"在线闭环。

| Q1 痛点基线：在肇庆东站接/送客平均排队多久？是否经历"前车不走、后车堵匝道"？知道其他落客点吗？ | 广州南 40-50min、北京南 20min、肇庆东严管/劝离数据 |

| Q3 自损容忍度（校准 30s）：系统让你"最多多等 30s/1min/2min"换整体更快的可接受上限？ | 30s 目前是设计假设，无公开数据——需实测校准 |
| Q4 预约机制接受度：愿提前预约"某时段驶入某路段"吗？对"未预约记分/罚款"式规则的接受度？什么补偿（积分/短途优先）才愿意？ | 深圳预约通行、BCR 公平性、Metropia 积分 |
