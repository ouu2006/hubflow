# 填表报告（T1~T9）· V1.1

> **这份文档解决一件事**：**每次提交（PR）都要写一条填表报告——这次动了哪张表、哪一版、转成哪个产物、对着哪条判定、过没过。** 报告写在本文件末尾的**填表报告台账**里（机器可读的表格），PR 描述里放一句指针指过来。
>
> **为什么要有它**：业务数据只从表格进（**表格是唯一入口**，见 [`表格模板说明.md`](表格模板说明.md) 第 1 节）。表格实体在**共享盘**上，仓库里看不见——于是"**这一版 JSON 是哪张表第几版转出来的、有没有人绕过表格直接改 JSON**"这件事就没人答得上来。本报告把这条链子**钉在每次提交上**：**先有表，后有产物；产物的每一次变动，都要在一次提交里说清出处。**
>
> **配套文档**：[`表格模板说明.md`](表格模板说明.md)（九张表的列定义、填表纪律、转换脚本约定）、[`协作规范.md`](协作规范.md) 第 4 节（PR 与三道关）、[`开发规范.md`](开发规范.md) 第 7 节（表格转换脚本硬要求）、[`数据契约.md`](数据契约.md)（`stations/` 下每个 JSON 的字段）。

## 一、一句话口径

> **表在共享盘，产物在仓库，报告在提交里。**

| 在哪 | 是什么 | 谁动 |
|---|---|---|
| **共享盘** | T1~T9 表格实体（`.xlsx`，文件名带日期与版本，**永不覆盖**） | **池·S / 池·P / 池·Q** 填；队长复核 T8 |
| **仓库 `stations/`** | 表格转换脚本的产物（`points.json` / `network.json` / `demand.json` …） | **转换脚本**写；**不许手改** |
| **仓库 `docs/填表报告.md`**（本文件） | **填表报告台账**：每次提交一行，说清"哪张表第几版 → 哪个产物" | 提交者在 PR 里补 |

**仓库里没有 `.xlsx`**（`doc_gate.py` 第 2 组检查直接拦），所以**报告只写"表格的文件名 + 版本"，不写共享盘的绝对路径**（与"团队记录不写本机绝对路径"同一口径，见 [`技术方案与实施手册.md`](技术方案与实施手册.md) 修订表第 39 条）。

## 二、什么时候要写（**触发条件**）

| 这次提交… | 要不要写报告 |
|---|---|
| **动了 `stations/` 下的任何 `*.json`**（新增 / 改数 / 删条目 / 只改来源记录也算） | ✅ **必写一行** |
| **动了表格转换脚本**（`work/engine/ingest_t*.py`、`work/twin/` 下的 T3~T6 转换脚本） | ✅ **必写一行**（"表 → 产物"的关系没变也要写，证明脚本改动可追溯到某张表） |
| **只是加注释 / 只改脚本内部实现、产物字节完全没变** | ✅ 仍写一行，`结果` 填 `已转`——**幂等重跑本来就不该有 diff**，"跑了脚本、产物没变"正是要留痕的那种情况 |
| **表格实体第一次建出来 / 升了版本**（哪怕产物还没转） | ✅ 写一行，`结果` 填 `待转` |
| **产物在场，但它是结构骨架 / 直接运行产物 / 还没有表格出处** | ✅ 写一行，`结果` 填 `占位`——**登记"它是什么"**，别让它无名无姓地躺在仓库里（见第 3.1 节） |
| **完全没碰表格与 `stations/`**（纯前端 / 纯文档 / 纯孪生代码） | ⬜ **不用写**；PR 描述里填一句"本次不涉及填表报告"即可 |

> ⚠️ **行数由改动量决定，不由 PR 大小决定**：一次 PR 里动了三张表转出的产物，就写三行；只动了一条路段，就写一行。**没有"这次改动小就不写了"这回事**——恰是"小改动悄悄改一个 JSON"最容易变成没人知道谁改的。

## 三、怎么写（**七个字段，逐条说清**）

| 字段 | 填什么 | 反例（不许这样写） |
|---|---|---|
| **表** | `T1`~`T9` 里的哪一张；跨表就填 `T1+T2` | "站点数据" |
| **提交者** | 谁提交的这个 PR（GitHub 账号名） | "我" |
| **表版本** | 表格文件名 + 版本号，如 `T2_路段属性核对表_20261015_v4.xlsx`；**没表就填"无（基线）"** | "最新版" |
| **产物** | 仓库里的相对路径，如 `stations/network.json` | "站点包" |
| **依据** | **照抄**"完成判定"的原文（`表格模板说明.md` 第 3~10 节的填表纪律、或手册第 17 章 `TC-xx` / `M1-x`）**不许自己改写** | "数据没问题" |
| **结果** | **只许五种**：`已转` / `已核对` / `占位` / `未重跑` / `待转`（对"过没过"的正式判定是 T7 **池·Q** 的活，报告只如实登记） | "基本通过" |
| **日期** | `YYYY-MM-DD` | "今天" |

### 3.1 `结果` 五种取值怎么用

| 结果 | 填什么 | 底下发生的事 |
|---|---|---|
| **已转** | 表格（新版本）在共享盘，脚本重跑**成功**——产物在**本次提交**里有 diff，或重跑后**逐字节一致**（幂等重跑的正常结果） | **唯一一种"表格推动产物"的正常状态** |
| **已核对** | 表格**没有变**，本次只是对着表格复核 / 补来源记录；产物要么没变，要么只改了来源记录 | 复核留痕 |
| **占位** | **产物在场，但它还没走到"表格 → 脚本"这一棒**：① **结构骨架**（W0 只定字段形状、值是占位样例，如 Issue #39 的 `stations/` 九件）；② **直接运行产物**（脚本跑出来就有、不经过表格，如模块的 `out/*.json` 若进仓库）；③ **基线登记**（先登记在场事实，表格与脚本都还没到位） | **门禁只打 `[注意]`**：它既不是"还没转"，也不是"有表格出处"；**合并前要在 PR 里说清它是什么** |
| **未重跑** | 产物变了（或本应在场），但**没有跑转换脚本**（手动改数、或改脚本但没重跑） | **门禁会点名**（见第四节）；合并前要在 PR 里说明为什么，不能就这样算了 |
| **待转** | **产物本来就该在仓库里，但这次提交没带上**——表格已建 / 已升版本而产物还没生成；也用于**基线登记**（表格实体与转换脚本都还没到位，见 Issue #43 / #41） | **门禁会点名；在补齐之前，这个 PR 不视为完成** |

> **`已转` 一定要带上去重跑的证据**：命令、读了多少行 → 生成多少条、产物前后 diff。**只有表格没有产物、或只有产物没有表格，都不算"已转"。**

### 3.1.1 `占位` 的界线（**两个方向都要守住**）

> ① **不许用 `占位` 吞掉"该由表格来的产物"**——一份有表格出处、却是手工改出来的 JSON，写 `占位` 就是拿它当挡箭牌，那属于 `未重跑`；
> ② **也不许给结构骨架硬写 `已核对`**——"对着表格复核"这件事根本没发生（表格实体还没建），写上去就是假账。
>
> **什么时候必须换成 `已转`**：该产物的第一版从表格转出来时，**加一行 `已转`**（`占位` 那行**不要改** —— 台账只追加，历史留痕）。`占位` 说的是"我当时是占位样例"，这句话永远成立。
>
> **一行只覆盖它点名的那几个产物（通配不展开）**：解析「产物」列时只认**写全的文件路径**（`stations/xxx.json`）——写 `stations/*.json` 这种通配**一个文件也覆盖不了**，那一行就只是说明，不是覆盖。所以每来一件新的 `stations/*.json`，都要**另补一行**点名它；旧行吞不掉新文件。

| 表 | 提交者 | 表版本 | 产物 | 依据 | 结果 | 日期 |
|---|---|---|---|---|---|---|
| **T2** | `@`（提交者） | `T2_路段属性核对表_20261015_v4.xlsx` | `stations/network.json` | 表格模板说明第 4 节：底图核对列无空白、不一致必须写差异原因（TC-15 前置） | 已转 | 2026-10-15 |

## 四、机器怎么判（CI 的门禁口径）

**本地与 CI 是同一条命令**：`python scripts/doc_gate.py`（检查名 `ci`，见 [`协作规范.md`](协作规范.md) 第 4 节）。除原有六组检查外，新增**第 7 组「填表报告台账」**，只查机器判得动的事：

| # | 查什么 | 怎么判 | 判不过会怎样 |
|---|---|---|---|
| ① | **台账格式** | 每行七个字段齐全；`结果` 只能是 `已转` / `已核对` / `未重跑` / `待转` 之一；日期是 `YYYY-MM-DD` | **判失败**，指出行号 |
| ② | **产物覆盖** | 本次提交（本地 = 已暂存 + 未提交；CI = PR 相对于 base 的改动清单）里**每一个 `stations/*.json` 的改动**，台账里都要能找到对应的行 | **判失败**，列出没被覆盖的文件 |
| ③ | **结果语义** | 在**本次改动**的产物里，覆盖行的 `结果` 必须是 `已转` / `已核对`（产物在场却写着"还没转"自相矛盾） | **判失败**，指出行号 |
| ④ | **日期对账** | 覆盖行的日期应与"该产物最近一次改动"**同一天**（取**作者日期**：变基 / 压缩合并会重写提交日期但保留作者日期） | **只打 `[注意]`，不判失败**——日期对不上可能只是 rebase 的副产物，但"覆盖行是旧的"必须看得见，否则老行会把新改动吞掉 |
| ⑤ | **`结果` 待办提醒** | 台账里写着 `未重跑` / `待转` 的行（且指向产物） | **只打 `[注意]`**：这类行就是在说"还差一次转换"，需要有人在 PR 里说明，不能就这样算了 |

**这组检查拦不住的（写清楚，别误以为它全包了）**：台账里的表格文件名与版本**是不是真的存在**（共享盘在仓库外，CI 看不到）、`已转` 是不是真跑过脚本、产物数值与表格数值是否逐条对得上。这几件只能靠**人 + 池·Q 复核**：**"口径与判定不变"的承诺面、人审覆盖的部分，不因为加了这组检查而缩水。**

> **本地怎么拿"本次改动清单"**：第 7 组检查依次看 ① CI 传进来的 `DOC_GATE_CHANGED_FILE`（改动清单文件，PR 相对 base）→ ② 内联的 `DOC_GATE_CHANGED` → ③ 本地 git（`diff HEAD` + 未跟踪文件）。**传了空清单 = "本次确实没改文件"；什么都不传 = "不知道改了什么"，门禁打 `[注意]` 但不判失败。** **这组检查只看这份文档与产物**：本文件存在 → 至少校验台账格式（仓库里一个 `stations/*.json` 都没有时，覆盖与日期两项自然无事可查，判 `[通过]`）；**本文件不存在 → 判失败**（少了它就没法登记出处）。**它不会空转**：台账一行都没有、或找不到台账章节，都直接判失败。
