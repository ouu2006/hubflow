## L3 指标判级层（B 自设计）

- **完成判定**：同输入连跑 3 次完全一致；M1-3 / TC-11；与人工判读一致率 ≥85%（样本视频抽验）。

## L4 决策层（B 自设计）

- **职责**：在指标与容量上算"该怎么分流"，出推荐+理由+预约。
- **输入**：`segments.json` + `demand.json` + 站点包。
- **输出**：`routes.json`（`status` 三态、`why`、租约 90s、harm_check）+ 预约簿快照。
- **量纲约束（硬）**：`x = q/c` 已是无量纲饱和度；**惩罚项不得再除以 c**——BPR 形式即 `t = t⁰(1+αx^β)`；流量/容量统一 pcu/h 同口径；α/β 按道路等级分组、参数外置站点包（代码 grep 不到魔法数）。公式形式 owner 自定，量纲与外置是边界。
- **算法边界**：不伤害约束 `min{30s, +5~10%}`；饱和度 ≤0.85；再疏导 60s/≤2 次/10% 滞回；反效果回滚 >5%；拥堵转移率 ≤0；不 import traci/cv2。
- **内部设计授权**：**公式形式 owner 自定，量纲与外置是边界**——候选路径生成与 k 短路实现、行程时间与预约 / 再疏导的具体算法与步骤、时段粒度与数据结构、伪代码怎么落地——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。**契约边界**：`routes.json` 字段名 / 类型 / 必填与三态 `status`；上一条「算法边界」里的全部数值（30s / 0.85 / 60s / 2 次 / 10% / 5% / ≤0）；量纲口径（`x` 无量纲、惩罚项不再除 `c`、统一 pcu/h）与参数外置（代码 grep 不到魔法数）。
- **完成判定**：mock 喂入即出 routes（自检④）；M1-4 / **TC-17 按 01§3 评测协议**（固定种子车辆群、评估期关在线增删车、四计数统计）。

## L5 出口层（C 自设计）

- **职责**：把决策翻译给人；采集采纳事件。

- **输出**：Vue 管理端 + ArkTS App + 端点 + `adoption.event`。
- **边界**：不含决策逻辑；**双端同源举证**（同一数值指回同一快照同一 `ts`，不许两端各算）；红档 10s 切应急；地图仅在线调用+零持久化（ToS 条款已核）。
- **内部设计授权**：页面结构、组件划分与状态管理 · 端点包装与推送方式 · 轮询 / 缓存 / 渲染与交互细节 · 地图 SDK 选型与调用封装——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。**契约边界**：消费的四份快照字段名 / 类型；双端同源举证（同一数值必须指回同一快照同一 `ts`，不许两端各算）；红档 10s 切应急；地图仅在线调用 + 零持久化（ToS 条款已核）。
- **完成判定**：M1-5 / TC-19 / TC-02~10；mock `routes.json` 即可渲染页面壳（不依赖 L2/L4）。
