# HubFlow 模块要求书（中心文档③ · 六份一页纸）

> 性质：**中心文档**——每模块一页：职责/输入输出契约/非功能边界/完成判定。**内部设计（怎么实现）由 owner 自定**，落位 `work/<module>/DESIGN.md`，中心只审契约边界。
> 参考资料：`./99-参考-系统架构建议.md`（实现建议库，不是规范）、[`../hubflow-data/03`](../hubflow-data/03_技术事实_SUMO与数据同化.md)（SUMO 技术事实）。
> 通用非功能（所有模块）：确定性可回放（同种子同输入同输出）；金样例自检通过；`is_simulated` 口径按上游契约 §八。

---

## L1 站点包（B 定结构 · 协作成员认领填数，系列 S/V）

- **职责**：全站配置唯一事实源；换站只改本层。
- **输入**：OSM、踏勘事实（系列 S 认领者）、标定控制点（系列 V 认领者）、12306 时刻表。
- **输出**：`stations/` 九件 + `sumo/`；v2.1 增补：PCU 系数表、断面映射字段（02§P2）、时间映射参数（02§P3）、`assimilation` 开关。
- **边界**：静态无运行时状态；引擎代码 grep 不到站点名/坐标/路名。
- **完成判定**：M1-1 / TC-15；换站演练只改 `stations/`。

## L2 世界层（A 自设计）

- **职责**：拥有"实际发生了什么"；双源出 `detectors.raw`；同化只灌边界断面。
- **输入**：站点包、6 段样本视频、场景/因素注入。
- **输出**：`detectors.raw`（v2.1：逐指标有效性/断面映射/时间映射）、`assimilation_state.json`（含累计 inserted/removed）。
- **边界（不负责）**：判级与决策；不认识"等级"；同化不伸进 internal 断面；断面适配器**代码归 A、日常运行进任务池系列 V**。
- **内部设计授权**：E1+E2 还是车辆聚合、ViewTransformer 细节、calibrator 参数与门控实现、行为体遵从率建模——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。
- **完成判定**：M1-2 / M1-9（≤3px + 最远检查点 ≤5~8px）/ M1-10 + TC-20 四项 / TC-19 双源同屏。

## L3 指标判级层（B 自设计）

- **职责**：原始观测 → 结构化路况（四指标 + 等级）。
- **输入**：`detectors.raw` + `thresholds.json` + `factors.json`。
- **输出**：`segments.json`（v2.1）。
- **边界**：防抖内部消化；无车辆个体；**不按 source 分支**；不缺测外推。
- **内部设计授权**：判级流程的步骤划分与顺序、因素合成与防抖的具体实现 · 数据结构与中间产物形式 · 各档比较与聚合的写法——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）与判定。**契约边界**：`segments.json` 字段名 / 类型 / 必填；等级编号与各档阈值及各类【待标定】数值；不得按 `source` 分支；「数据不可用」灰态判定。
- **完成判定**：同输入连跑 3 次完全一致；M1-3 / TC-11；与人工判读一致率 ≥85%（样本视频抽验）。

## L4 决策层（B 自设计）

- **职责**：在指标与容量上算"该怎么分流"，出推荐+理由+预约。
- **输入**：`segments.json` + `demand.json` + 站点包。
- **输出**：`routes.json`（`status` 三态、`why`、租约 90s、harm_check）+ 预约簿快照。
- **量纲约束（硬）**：`x = q/c` 已是无量纲饱和度；**惩罚项不得再除以 c**——BPR 形式即 `t = t⁰(1+αx^β)`；流量/容量统一 pcu/h 同口径；α/β 按道路等级分组、参数外置站点包（代码 grep 不到魔法数）。公式形式 owner 自定，量纲与外置是边界。
- **算法边界**：不伤害约束 `min{30s, +5~10%}`；饱和度 ≤0.85；再疏导 60s/≤2 次/10% 滞回；反效果回滚 >5%；拥堵转移率 ≤0；不 import traci/cv2。
- **内部设计授权**：**公式形式 owner 自定，量纲与外置是边界**——候选路径生成与 k 短路实现、行程时间与预约 / 再疏导的具体算法与步骤、时段粒度与数据结构、伪代码怎么落地——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。**契约边界**：`routes.json` 字段名 / 类型 / 必填与三态 `status`；上一条「算法边界」里的全部数值（30s / 0.85 / 60s / 2 次 / 10% / 5% / ≤0）；量纲口径（`x` 无量纲、惩罚项不再除 `c`、统一 pcu/h）与参数外置（代码 grep 不到魔法数）。
- **完成判定**：mock 喂入即出 routes（自检④）；M1-4 / **TC-17 按 01§3 评测协议**（固定种子车辆群、评估期关在线增删车、四计数统计）。

## L5 出口层（C 自设计）

- **职责**：把决策翻译给人；采集采纳事件。
- **输入**：`routes/segments/vehicles/assimilation_state` 四快照。
- **输出**：Vue 管理端 + ArkTS App + 端点 + `adoption.event`。
- **边界**：不含决策逻辑；**双端同源举证**（同一数值指回同一快照同一 `ts`，不许两端各算）；红档 10s 切应急；地图仅在线调用+零持久化（ToS 条款已核）。
- **内部设计授权**：页面结构、组件划分与状态管理 · 端点包装与推送方式 · 轮询 / 缓存 / 渲染与交互细节 · 地图 SDK 选型与调用封装——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。**契约边界**：消费的四份快照字段名 / 类型；双端同源举证（同一数值必须指回同一快照同一 `ts`，不许两端各算）；红档 10s 切应急；地图仅在线调用 + 零持久化（ToS 条款已核）。
- **完成判定**：M1-5 / TC-19 / TC-02~10；mock `routes.json` 即可渲染页面壳（不依赖 L2/L4）。

## L6 回流 + 横切底座（C 胶水 · B schema）

- **职责**：主循环按序调模块函数；统一唯一 `sim_ts`；契约读写校验；事件留痕与回放。
- **边界**：不含业务逻辑；契约校验 import B 的 pydantic 模型（C 不写 schema）；坏契约直接 crash 不带病流转。
- **内部设计授权**：主循环的调度与编排方式 · 事件留痕与回放的实现（存储形态、索引、重放驱动）· 日志与时间戳的采集写法 · 一键脚本组织——owner 自定，须在 DESIGN.md 说明并满足观测契约（02§P1）。**契约边界**：唯一 `sim_ts` 口径；契约校验一律 import B 的 pydantic 模型（C 不写 schema）；坏契约 fail-closed；事件全量留痕可回放（TC-13）。
- **完成判定**：M1-6 / M1-7 / TC-13 同场景完整回放；SQLite 事件全量时间戳。
