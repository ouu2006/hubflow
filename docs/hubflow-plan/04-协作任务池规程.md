# HubFlow 协作任务池规程（中心文档④ · 任务领取制）

> 性质：**操作规程**——协作成员×3 **不定岗**，从任务池（许愿池）认领；照做即完成，不含设计决策。**队长**（7 人中 1 人兼任，**不占代码目录、不参与认领**）不进池子，职责见文末。
> 运行规则见《01》§4：任务板=GitHub Issues；owner 发布（vibecoding 类挂齐三 prerequisite：输入样例/输出样例/自检脚本）；认领=self-assign+评论；流转=待领→进行中→待审→完成。
> **可单人，也可多人**：一条任务**1 个人接也行，几个人一起接也行**——组队在 Issue 评论里写明**成员与分工**（如 V1 双人独立标注、V3 三人组队对账）。**不预设谁干哪件活：谁认领谁干。**
> 三条认领规则：**验收回避**（Q 系列认领者≠产物生产者/运行者，开发不得领 Q）；**系列续领权**（同系列优先首启者续领，换人留交接）；**WIP≤2 + 卡 30 分钟 @队长**。
> 依据材料：[`../hubflow-data/00_数据收集总索引`](../hubflow-data/00_数据收集总索引.md)、[`./02-契约集与补丁`](./02-契约集与补丁.md)（契约 v2.1）。

## 0. 任务发布规则（owner 侧）

**谁拆活**：**区域 owner**——**开发A 孪生与路况 / 开发B 决策与定位 + 判级 / 开发C 接口与双端**——负责把自己区域的活**拆到"半天可完成、独立可验"的小任务**（L0 / L1 / L2）后发布；**只发布、不点名、不指派**，一律池子认领（谁认领谁干，可单人可多人组队）。owner 对自己区域的产物做**日常技术复核**；**一期退出的独立验收仍走系列 Q + 回避规则（开发不得认领 Q）**。

**难度标签**（发布必打；认领者按自评领，**不给任何人设专属轨道**——擅长什么由认领历史自然涌现）：

| 标签 | 粒度 | 检验方式 |
|---|---|---|
| **L0 纯操作** | 跑命令/工具/填表格，零代码 | 规程清单 + 产物 |
| **L1 单脚本+骨架** | 半天量级（≤4h）；纯"文件进、文件出"的单一转换；**不做**状态管理、多文件协调、异常兜底 | 三 prerequisite（输入样例/输出样例/自检脚本）齐全 |
| **L2 多步/需自排错** | 多个子任务串联、要自己定位问题 | **暂不发布**；待有人以 L1 连续 3 个绿灯 PR 后由 owner 开放 |

**骨架填空（L1 必附）**：owner 发布 L1 任务时附**函数签名 + TODO 注释骨架**，认领者在框内填逻辑、不从零构架——骨架即隐性契约（函数边界与输入输出类型已定）。
**断点拆分**：超过半天的任务按**文件边界**拆（输入文件 → 中间产物文件 → 输出文件），每段一个任务、独立可验；中间产物也落文件。

## 系列 V · 视频线（操作类）

**V1 CVAT 标注**
1. 按 `02_视频链路` §3：类别 car/van/bus/truck（taxi 仅顶灯+涂装稳定可辨时单列）；最小框 ≥15×15px；遮挡 20~95% 标整框+`occluded`；顶灯按车体一部分。
2. 抽帧：同机位 1 帧/1~2 秒，6 段视频数百帧。
3. 质检：双人独立标注、分歧第三人仲裁、Kappa ≥0.8、抽检 10~20%（**双人/仲裁可跨认领者组队，在 Issue 标注**）。
4. 冻结：导出 COCO/YOLO+图片清单+哈希，只增版本不改历史 → Issue 交开发A。

**V2 控制点拾取（配合 M1-9）**
1. 每段视频拾 8~12 个**地面**控制点（标线中心/端点、路缘石；国标参照：虚线 6m/间隔 9m、车道 3.5/3.75m）。
2. 交开发A 跑标定；复核报告：控制点 RMSE ≤3px 且最远检查点 ≤5~8px，记录去畸变前后；不过→换点重跑并记录。

**V3 人工计数对账（TC-20 依据）**
1. 人员：断面 2 人（主计+复核）+ 视频侧 1 人同时窗——**恰好构成三人组队任务，建议整窗连领**。
2. 时窗 15 分钟×≥3 窗（早/平/晚），窗间休 5 分钟；记录方向/车道/分车型/窗号/计数员/异常。
3. 判定：总流量偏差 ≤5%、分车型 ≤10%；不一致先查时窗边界/漏检/遮挡，**不改视频原始输出**；歧义车单独登记。
4. 留证：同时窗录像留存。

**V4 断面适配器运行（代码归开发A）**
1. 跑 A 的适配脚本；核对映射表（ROI↔segment↔edge↔lane）与实际视频一致。
2. 监视输出：`miss:true`、逐指标 `valid:false` 出现即记录上报（Issue），不自行改参数。

## 系列 S · 站点与踏勘（操作 + vibecoding）

**S1 踏勘四合一**（一次出行，建议 2 人连领）：路网核对（OSM 打印图逐条对车道/走向）→ 信号路口拍照记相位（重点凤凰大道×吉庆大道、站前大道各口）→ 停车场实测（余位/闸机/蓄车场 80 位使用率）→ 视频采集（自采段+控制点测量+10~15 分钟对账录像，与 V2/V3 衔接）。
**S2 点位表维护**：`points.json` 填 `role=boundary/internal`+`sumo_edge_id`；边界断面清单整理后交**队长签字冻结**。
**S3 12306→demand.json（vibecoding）**：三 prerequisite 齐备才可认领；自检脚本跑绿即完成；PR 由 B 审。
**S4 netconvert 执行**：照 `03_技术事实` §1.1 命令清单复制粘贴；任何报错截图上报开发A，不自创参数。

## 系列 P · 参数与调研（操作类）

**P1 参数工作表**：把 `05_参数标定` §4 十项自标定参数落表（参数/区间/方法/责任/依赖数据），覆盖全部【待标定】。
**P2 问卷**：按 `04_需求侧` §5 五题执行（情景题优先），回收 ≥20 份有效。
**P3 竞品体验记录**：按 04 文档 §2 三层能力做体验记录与截图归档。
**P4 文档与演示物料**：按演示脚本 / PPT / 角标口径页 / 效果对比物料产出（**队长复核**）。**纪律**：每个数字都能在 T8 数据来源清单里找到出处；对外一律标「演示数据（模拟）· 双数据源」，**不得把模拟说成实测、不得把孪生说成真实仿真**。

## 系列 Q · 独立验收（验收类 · 回避规则生效）

> **认领限制**：本系列任何任务，认领者不得是被验产物的生产者或运行者；开发不得认领。判定值全部摘自手册与中心文档，勾不上就是没做完，不得自行放宽（PR#12）。

**Q1 契约校验复跑**：跑 `tools/validate_contracts.py`（好样例绿/坏样例红）→ 截图留痕。
**Q2 金样例回放**：TC-13 同场景重放，比对关键数值一致 → 记录。
**Q3 判定脚本复跑**：判级连跑 3 次一致性、TC-17 四计数表 → 截图。
**Q4 缺陷登记**：任何不一致记编号/复现步骤/截图；**不读代码、不改代码**，只记录上报。
**Q5 总验收（一期退出）**：出具署名验收记录（过/未过/条件）；**主签=本任务认领者，副签=另一名协作成员**；若 Q1~Q4 由多人分散认领，主签人须先汇总各任务记录。

## 队长规程（**队长** · 不进池子）

> 队长由 7 人中 1 人兼任；以下职责**即使兼任也显式保留**，**不得并入"对外对接"一句话**（照《01》§0 / §2.2）。**开发与协作成员一律不认领本节事项。**

**A. 拍板卡点（PR#17 五项）**：7 人名单落表、SUMO 许可结论、商业目的确认、**边界断面清单签字**、开发A 减负执行——每项一决策记录（日期/结论/依据）。
**B. 合规职责（显式保留）**：T8 数据来源清单维护；视频素材与地图 Key 授权申请；隐私告知文案；PIA 结论归档；**真实数据接入前的合规门禁**（一期→二期切换放行条件）。
**C. 对外**：站区管理方/交警二大队联络纪要。
**D. 任务池运维**：每周核一次池子（积压任务重派/拆分；认领冲突仲裁；交接记录抽查）。
**E. 答辩素材归档**：`04_需求侧` 三类弹药+查新结论，逐条标出处与可信度档位；【待核验】项答辩前清零。
**F. 仓库与文档**：**非代码 PR 合并**、`docs/` **计划类文档维护**（**显式保留**；分工口径见 [`../开发规范.md`](../开发规范.md) 第 3 节与 [`../协作规范.md`](../协作规范.md)）。

### 通用纪律（池子全员）

1. 三 prerequisite 缺一不接 vibecoding 任务；2. WIP≤2；3. 卡 30 分钟 @队长；4. 产出走 PR/Issue 由对应 owner 审；5. 每周日在完成度表自更自己认领的任务行（判定值照抄中心文档）；6. 续领权只作用于"同系列"，跨系列自由认领；7. **可单人、也可多人**：一条任务 1 人接或多人组队接都行（组队在 Issue 评论里写明成员与分工）；**不预设谁干哪件活——谁认领谁干**。
