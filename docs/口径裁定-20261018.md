## 二、四态定义与验收纪律（**不得混写**）

> 常说的「三态」指**通过 / 阻塞 / 不做**（交付登记口径）；台账另加 **未过**（已判不满足），合计四态。每行**只能取一个状态**。

| 状态 | 定义 | 典型例子（本台账） | 写错的样子 |
|---|---|---|---|
| **通过** | 判定原文**各子项**在本轮口径下已达成，且仓库内有可核证据（PR / 文件 / 命令 / 自检记录） | M1-1（W1）、M1-3、TC-11、C-1 | 「基本过」「差不多」「我机器上跑过」 |
| **未过** | 已执行或本该执行，但**结果不满足判定**（含交付物缺失、子项未实现） | TC-17② FAIL、TC-18 空壳、TC-12 `pickup_route` 缺 | 把 FAIL 写成「阻塞」或「部分通过」 |
| **阻塞** | 因**外部前置**（数据 / 签字 / 上游产物 / 下游接入（真孪生 / 同化）/ 授权）无法完成判定，**解除条件与责任人明确** | M1-2（仅视频侧 ≥60 点）、M1-9（2/6 视频）、M1-10（清单未冻结）、TC-15（T2 表不可得） | 把阻塞写成「通过」；或不写解除条件 |
| **不做** | **业主书面裁定排除**（本批：IKLLX9 App） | C-3、M1-5、TC-02、TC-05/TC-08、TC-12 App 侧 | 把「不做」写成「未做/阻塞」；或把「未做」写成「不做」 |

**纪律（照手册 17.4 + Issue IKMS1J 完成判定）**：

1. **四选一**：不写「基本过 / 基本完成 / 部分通过」；状态唯一。
2. **判定值不许改**：手册第 17 章门槛是唯一判定来源；要改走**手册修订 / 业主裁定**，台账与自测记录里**不许悄悄放宽**。
3. **判定做不了 = 阻塞，不是通过**：不得自行降标准；「环境缺数据」只能写阻塞。
4. **mock / 样例 / 未跑不得写成通过**：`is_simulated: true`、演示骨架、机制示例都**不能**当实测结论。
5. **不采信开发者自述**：池·Q **独立复跑**（尤其场景二开关对比与 TC-13 可复现性）；实测与自测不一致时**以池·Q 为准**。
6. **阻塞必须可行动**：每条写「解除条件 + 找谁」；**不做**必须写业主裁定来源（本文件 §一.2）。
7. **证据可追溯**：PR 号 / 仓库相对路径 / 命令 / 自检记录；**不写本机绝对路径**、不写「截图在我机器上」。
8. **口头口径落到本文件才算数**：YOLO 代号 / App 排除 / 摄像头 N 路 / M1-9 缺口四条已落纸（Issue IKMS1J 完成判定「业主口径落纸」）。
