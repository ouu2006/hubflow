## 1. 分支保护（Settings → Branches → Add branch protection rule，分支名 `main`）

已经开着的（不用动）：Require a pull request before merging ✅、Require approvals = 1 ✅、Dismiss stale approvals ✅、Require review from Code Owners ✅。

要补的四项，**按重要性排序**：

- [ ] **① Do not allow bypassing the above settings** —— 当前未开。**这是唯一能拦住 owner 自己合自己 PR 的一项**；不勾它，前面四项等于只拦别人
- [ ] **② Require status checks to pass before merging → 勾选 `ci`** —— 当前未开。`ci` 来自 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)（仓库里还注册着一个**已手动停用**的「自动审查」workflow，不影响本项）
- [ ] **③ Require conversation resolution before merging** —— 当前未开：审查意见没处理就不许合
- [ ] ④（可选）Restrict who can push to matching branches：只留队长

## 4. 复核方式（改完照着核一遍）

```bash
R=ouu2006/hubflow        # 换成实际 owner/repo

# ① 保护的**完整**配置：approvals / code owners / 禁止绕过 / 必需检查
#    ⚠️ 不要用 `gh api repos/$R/branches/main`：那个端点的 protection 字段只回 enabled 与
#       required_status_checks，永远看不到 approvals 与 code owners，没法用来判定。
gh api repos/$R/branches/main/protection

# ② CI 是否真的跑起来了（check 名应包含 ci）
gh pr checks <PR号> -R $R

# ③ 有没有作者之外的人类 Approve
gh pr view <PR号> -R $R --json reviews,reviewDecision \
  --jq '{decision:.reviewDecision, reviews:[.reviews[]|{a:.author.login,s:.state}]}'

# ④ 协作者名单（决定"人工同意"实际拦住了谁）
gh api repos/$R/collaborators --jq '.[]|{login,role_name}'
```

**判定**：① 输出里 `enforce_admins.enabled = true`、`required_status_checks` 含 `ci`、`required_conversation_resolution.enabled = true`；② `gh pr checks` 里能看到 `ci`；③ 有**作者之外**的账号留下 `APPROVED`，且 `reviewDecision` 不再是 `REVIEW_REQUIRED`；④ 协作者名单与 7 人一致。
