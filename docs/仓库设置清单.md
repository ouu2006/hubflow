> **一句话**：**机器拦得住的只剩两件** —— ① 必须走 PR；② `ci` 必须绿。**"三道关"（自查 / 快速独立审查 / **兜底审三人任一**）是团队纪律，平台替你们拦不了；代码互审已于 2026-10-10 取消。**

## 1. 分支保护（Gitee：仓库 → 管理 → 保护分支设置）

**入口**：`https://gitee.com/ozxowx/hubflow/branches/setting`（页面右侧可直接切到 `main`）。

**⚠️ Gitee 的模型与 GitHub 有两处不一样，先说清**：

1. **保护分支有两层，两层都要配**：① 把分支的**属性**设为「保护分支」（`常规分支` / `保护分支` / `只读分支` 三选一）；② 在**保护分支规则**里写一条匹配 `main` 的规则。**规则只对「保护分支」属性生效**——只写规则不设属性 = 规则空转（页面原文）。
2. **"要求门禁状态成功才能合并"是一个勾选项**（规则表单里的 `要求门禁状态成功才能合并`），不是独立开关；勾上之后，**必须先推到另一条分支、待检查项通过后才能并进 `main`**。

**已按 2026-10-10 决定配好（迁到 Gitee 后逐项对一遍）**：

- ✅ **分支属性 = 保护分支** —— `main` 不许直接推
- ✅ **保护分支规则匹配 `main`，权重 1**
- ⏳ **要求门禁状态成功才能合并** —— **需先在 gitee_go 页开通流水线**（见第 3 节），开通后再勾；否则勾了也没有检查项可选
- ❌ **不需要"必须人工 approve"** —— 沿用 2026-10-10 决定，人审是纪律不是设置
- ❌ **规则白名单** —— 留空（白名单是"符合规则但允许不是保护分支"的例外名单，一期不用）

**分支命名（2026-10-10 起，全仓统一，与平台无关）**：

- **常驻个人分支已取消**（5 条 `feat/*` 已删，无独有提交，删除不丢代码）；
- **一条任务一条短分支**：`task/<Issue号>-<简述>`（例：`task/12-t1-points`），**合并后删除**；
- **文档类修订走 `docs/<主题>`**；
- `main`：**不许直推**，必须 PR + **`ci` 绿**。

**还**可以**再补的（都不是必须）**：

- [ ] **评审模式**（规则表单里的另一档，与"标准模式"二选一）—— 会按仓库的**代码审查设置**自动指派预设人员名单。**一期不启用**：团队 7 个账号在 Gitee 上尚未重建，指派不到人。**队长建好账号后**再加，并同步本页
- [ ] **推送规则设置**（`/push_config`）—— 可限制提交信息格式等；一期不启用
- [ ] **保护标签设置**（`/tag_rules`）—— 一期不打标签，不启用

## 3. 流水线（Gitee Go）

**⚠️ 与 GitHub Actions 最大的差别：Gitee Go 是增值服务（预付费按构建时长），需要手动开通，且有免费额度限制。**

**实测（2026-10-14）**：`https://gitee.com/ozxowx/hubflow/gitee_go` 页面显示 **"开通 Gitee Go"** 按钮，账户页 **剩余时长 0 分钟 —— 无开通 Gitee Go 仓库**。也就是说：

- **配置文件已经就位**：`.gitee/workflows/ci.yml`（检查名 `ci`，跑 `python3 scripts/doc_gate.py`，与本地完全同一条命令）；
- **但流水线尚未开通，这个文件现在不会被执行**。开通后才会跑第一次。

**两条路，队长二选一**：

- [ ] **路线 A（默认推荐）：本机当门禁** —— 每次提交前自己在仓库根跑 `python scripts/doc_gate.py`（**与 CI 同一条命令、同一份内容**，门禁读的是 git 索引里的 blob，不会出现"本地绿、CI 红"）。PR 里把命令与结论贴进「怎么验证的」栏。**代价是"红了也合得动"**，靠纪律；
- [ ] **路线 B：开通 Gitee Go** —— 开通后 `ci` 才会真的跑；再回到第 1 节勾上「要求门禁状态成功才能合并」，就恢复成"红了合不了"。**代价是要买时长**。

> **两条路的选择记录在 Issue 里**（迁移落地单）。选定之后：路线 A 要把"`ci` 必须绿"这句话改成"**本地门禁必须绿**"（[`协作规范.md`](协作规范.md) 第 4 节、[`开发规范.md`](开发规范.md) 第 11/12 节、`README.md` 相关表述），路线 B 不用改。

- [x] 工作流文件落地 `.gitee/workflows/ci.yml`（检查名 `ci`）
- [ ] **决定走路线 A 还是路线 B**（队长）
- [ ] （路线 B）在任一 PR 上确认 **`ci`** 这个 check 真的出现，且名字与第 1 节勾的名字**逐字一致**

```text
   判定：名单与实际参与的人一致（现在这一项是唯一的防线）。
```

**走命令行**（仓库侧，任何成员都能跑）：

```bash
R=git@gitee.com:ozxowx/hubflow.git

# ④ 远端分支清单（合并后该删的分支还在不在）
git ls-remote --heads $R

# ⑤ 本地跑一遍门禁（与流水线同一条命令）
python scripts/doc_gate.py
```

> ⚠️ **Gitee 没有 `gh api .../branches/main/protection` 这样的公开读端点**（三个候选端点实测全 404），所以**分支保护的"实测"只能靠页面截图或人工确认后写进本页**——这是与 GitHub 侧最实质的一次退化，记录在案。
