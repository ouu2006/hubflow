>
> **2026-10-10 调整（业主决定）：取消"必须人工 approve"这道卡，把门槛从"人"换成"机器"。**
> 依据：PR #12–#21 **全部**停在 `reviewDecision = REVIEW_REQUIRED`，**却全部由作者本人（仓库 admin）合掉**——能合的原因就是 `enforce_admins = false`。也就是说**这道卡对 admin 从未真正生效**，它只卡住另外 5 个 write 成员，代价是每个 PR 永远挂一个红叉。改后：**机器只强制两件事（必须走 PR + `ci` 必须绿），人审降级为团队纪律**（见 [`协作规范.md`](协作规范.md) 第 4 节）。
>
> **2026-10-10 实测**（`gh api repos/ouu2006/hubflow/branches/main/protection`，需管理员权限）：
>
> | 设置项 | 实测 | 说明 |
> |---|---|---|
> | Require a pull request before merging | **开** | 不允许直接推 `main`（`required_pull_request_reviews` 对象存在） |
> | `required_approving_review_count` | **0（已取消）** | **不再要求人工 approve** |
> | `require_code_owner_reviews` | **false（已取消）** | CODEOWNERS 仍会自动带上 Reviewer，但**不阻塞合并** |
> | `dismiss_stale_reviews` | **false（随上一项取消）** | 已经没有"必须 approve"，也就没有"作废旧 approve" |
> | `required_status_checks` | **`ci`（已开）** | **现在唯一的自动门禁**，来自 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) |
> | `enforce_admins.enabled` | **false（未开）** | admin 仍可绕过——**但现在连"绕过"都不需要了**，因为没有必须满足的要求 |
> | `required_conversation_resolution` | **false** | 审查意见没处理也能合（靠纪律，不靠设置） |
>
> **一句话**：**机器拦得住的只剩两件** —— ① 必须走 PR；② `ci` 必须绿。**"四道关"（自查 / 快速独立审查 / 互审 / 队长兜底）是团队纪律，GitHub 不再替你们拦。**

## 4. 复核方式（**下次复核照着这个判定**）

```bash
R=ouu2006/hubflow        # 换成实际 owner/repo

# ① 保护的**完整**配置：有没有 approve 要求 / 必需检查 / 能否绕过
#    ⚠️ 不要用 `gh api repos/$R/branches/main`：那个端点的 protection 字段只回 enabled 与
#       required_status_checks，看不到 approvals，没法用来判定。
#    ⚠️ GitHub 的分支保护 API **没有单独的「要求 PR」开关**：`required_pull_request_reviews`
#       这个对象在 = 「Require a pull request before merging」开着（approvals 可以是 0）。
gh api repos/$R/branches/main/protection \
  --jq '{pr_block_present:(.required_pull_request_reviews != null),
         approvals:.required_pull_request_reviews.required_approving_review_count,
         code_owner:.required_pull_request_reviews.require_code_owner_reviews,
         checks:.required_status_checks.contexts,
         enforce_admins:.enforce_admins.enabled}'

# ② CI 是否真的跑起来了（check 名应是 ci）
gh pr checks <PR号> -R $R

# ③ 协作者名单（现在是唯一防线）
gh api repos/$R/collaborators --jq '.[]|{login,role_name}'
```

**下次复核的判定**（2026-10-10 的实测值就是下面这一组）：① `pr_block_present = true`、`approvals = 0`、`code_owner = false`、`checks` 含 `ci`；② `gh pr checks` 里能看到 `ci` 且结论是 `SUCCESS`；③ 协作者名单与实际参与的人一致。
