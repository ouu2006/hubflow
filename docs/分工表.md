# 分工表（位置 → 任务 → 交付物 → **完成判定**）

> **本文档解决的问题**：技术手册第 15 章写了"七个位置各干什么"，但**没有落到三件事**：谁做、这一周做什么、**干到什么程度才算完成**。本表把它补上。
>
> **使用方法**：
> ① 队长在总表填「负责人」与「GitHub」两栏；
> ② 每人只看自己那一节：**任务 → 交什么文件 → 怎么算做完**；
> ③ 站会只说一句话：**"我交了哪个文件、对着哪条判定、过没过"**；
> ④ 验收岗按第四节的判定逐条打勾，**打不出勾就是没做完**。
>
> **判定值的来源**：全部摘自技术手册（第 5/6/14/17 章），**本表不新造任何数字**。带【待标定】的是 demo 假设值，引用时必须照抄这个标记。

## 三、口径与纪律（每人必读）

| 项 | 口径 |
|---|---|
| **模拟数据标注** | 一期全部数值为演示数据（模拟），**每个数值带 `is_simulated: true`**，对外一律标「演示数据（模拟）」 |
| **不把旁路说成验证** | **一期 `.ckpt` 已就绪，默认走 MindSpore**，不再需要旁路。若确要走旁路，自测报告必须写明「本次演示未验证 MindSpore 推理链路」 |
| **不把单站说成可复制** | 一期单站（肇庆东站）；第二站只做**配置离线验证**，不建实景 |
| **不把孪生体说成真实仿真** | 孪生体是**机制验证工具**，不是"真实交通仿真结果"；用途一（产生数据）与用途二（对照实验）的结论**不得混在一句话里说** |
| **契约变更** | 改 `segments.json` / `routes.json` / `render.json` 字段**必须当天在 Issue 里说**，由决策线裁定 |
| **大文件与密钥** | 视频 / 权重 / 数据集 / `.env` 一律不进仓库（见 [`开发规范.md`](开发规范.md) 第 11 节） |
| **卡住怎么办** | 按手册开篇纪律：**按默认口径先做下去，再提出来讨论，不要停下来等** |

```text
① 在第一节总表里填「负责人」与「GitHub」两栏（开发组缺 2 人）
② 邀请开发组成员为 GitHub 协作者（Settings → Collaborators）
③ 裁定中文路径问题（现状核实 4.3 三选一方案）—— 这是 M1-1 的前置
```

> 填完①之后，由后端按本表第二节建 Issue（每条任务一个 Issue，按位置打标签），开发组即可按 Issue 开工。
> **Issue 里请把对应任务的「完成判定」一并贴进去**——否则开发组只知道要交什么文件，不知道要做到什么程度。
