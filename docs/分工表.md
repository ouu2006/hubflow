# 分工表（位置 × 周 → 任务 → 交付物 → **完成判定**）

> **本文档解决的问题**：技术手册第 15 章写了"七个位置各干什么"，但**没有落到三件事**：谁做、这一周做什么、**干到什么程度才算完成**。本表把它补上，并按 **W0–W8 全周期**展开。
>
> **使用方法**：
> ① 队长在总表填「负责人」与「GitHub」两栏；
> ② 每人只看自己那一节：**这周的任务 → 交什么文件 → 怎么算做完**；
> ③ 站会只说一句话：**"我交了哪个文件、对着哪条判定、过没过"**；
> ④ 验收岗按第五节的判定逐条打勾，**打不出勾就是没做完**。
>
> **判定值的来源**：全部摘自技术手册（第 5/6/14/17 章与第 15.8 里程碑），**本表不新造任何数字**。带【待标定】的是 demo 假设值，引用时必须照抄这个标记。
>
> **周期口径**：W0–W8 是"人力可投入情况下的建议值"，**不是承诺工期**（手册 15.8）。

## 三、口径与纪律（每人必读）

| 项 | 口径 |
|---|---|
| **模拟数据标注** | 一期全部数值为演示数据（模拟），**每个数值带 `is_simulated: true`**，对外一律标「演示数据（模拟）」 |
| **不把旁路说成验证** | **一期 `.ckpt` 已就绪，默认走 MindSpore**，不再需要旁路。若确要走旁路，自测报告必须写明「本次演示未验证 MindSpore 推理链路」 |
| **不把规则后处理说成微调** | 数据量不足时**不微调**是手册 14.1 认可的降级路径，改装「顶灯 + 车身颜色」规则区分出租车与私家车。**但必须在自测报告里如实写明"未做微调"，不得表述为"模型已微调"**（同上是"跑通"与"验收"两条线的纪律） |
| **不把单站说成可复制** | 一期单站（肇庆东站）；第二站只做**配置离线验证**，不建实景 |
| **不把孪生体说成真实仿真** | 孪生体是**机制验证工具**，不是"真实交通仿真结果"；用途一（产生数据）与用途二（对照实验）的结论**不得混在一句话里说** |
| **不把 SUMO 里跑的车和自研体里的车当成两批** | 分工写死在手册 **10.2 节**：SUMO 跑交通流物理执行、自研体通过 TraCI 管司机决策，**必须是同一批车**（坑表第 16 条） |
| **契约变更** | 改 `segments.json` / `routes.json` / `render.json` 字段**必须当天在 Issue 里说**，由决策线裁定 |
| **大文件与密钥** | 视频 / 权重 / 数据集 / `.env` 一律不进仓库（见 [`开发规范.md`](开发规范.md) 第 11 节） |
| **卡住怎么办** | 按手册开篇纪律：**按默认口径先做下去，再提出来讨论，不要停下来等** |
