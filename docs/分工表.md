## 2. 职责补丁（复查缺口，必须并入）

1. **独立验收机制**（不得由开发兼任）：验收类任务进任务池（**系列 Q**），由**回避规则**保证独立性——认领验收任务者**不得是该产物的生产者或运行者**；**一期退出的署名验收记录**由"总验收"任务认领者**主签**、另一名协作成员**复核副签**。**开发一律不得认领验收任务。**
2. **队长合规职责**（P2-0）：T8 数据来源清单、视频与地图授权申请、隐私告知、PIA、**真实数据接入前的合规门禁**——**即使兼任也显式保留，不并入"对外对接"一句话。**

## 3. TC-17 评测协议（A/B 实验因果性）

写进完成判定，不是任何人的内部设计：

1. 先开同化生成统一需求与初始状态，随后**固定随机种子与车辆群**（显式 `<vehicle>` / `<trip>` 需求文件；`saveState` 平台相关慎用）；
2. **评估期关闭在线 calibrator 增删车 / 清堵**（或明确声明为"完整闭环实验"并单列，**不得与算法收益混同归因**）；
3. 配对跑疏导**开 / 关两遍**，统计 **inserted / removed / not_entered / completed** 四计数；
4. KPI（总耗时、先入车不恶化、转移率 ≤ 0）**只在与共同车辆群可比的口径上比较**。

## 4. 任务池（许愿池）认领机制

**任务板 = GitHub Issues**。任务由**对应 owner 发布**（vibecoding 类必须挂齐三 prerequisite：**输入样例 / 输出样例 / 自检脚本**，缺一不得发布；**发布必打难度标签 L0 / L1 / L2，L1 必附骨架与断点拆分**）；协作成员 **self-assign + 评论"认领"** 即锁定。

**状态流转**：待领 → 进行中 → 待审（Issue 附产物 / PR）→ 完成（owner 审过关闭）。

**三条认领规则**：

| # | 规则 | 目的 |
|---|---|---|
| 1 | **验收回避**：系列 Q（验收）任务的认领者 ≠ 该产物的生产者 / 运行者；**开发不得认领 Q** | 独立验收不采信自述（上游 §4.6） |
| 2 | **系列续领权**：同系列任务（如 CVAT 批次、对账窗口）优先由首启者续领；换人须留交接记录（要点 + 坑） | 标注 / 计数等技能有学习成本，避免反复重学 |
| 3 | **WIP ≤ 2 + 30 分钟上报**：每人同时进行中任务至多 2 个；卡住 30 分钟在 Issue @队长 | 防闷头耗时间（收紧自上游"2 天"） |

**四个系列与示例**（详细规程见 [`hubflow-plan/04-协作任务池规程.md`](hubflow-plan/04-协作任务池规程.md)）：

| 系列 | 内容 | 类型 |
|---|---|---|
| **V 视频线** | CVAT 标注、控制点拾取、人工计数对账、断面适配器运行 | 操作 |
| **S 站点 / 踏勘** | 踏勘四合一、点位表维护、12306 → demand、netconvert 执行 | 操作 + vibecoding |
| **P 参数 / 调研** | 参数工作表、问卷、竞品记录、**文档与演示物料**（队长复核） | 操作 |
| **Q 独立验收** | 校验器复跑、金样例回放、判定复跑、缺陷登记、总验收署名 | 验收（回避规则） |
