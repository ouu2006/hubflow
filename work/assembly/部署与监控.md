## 2. 部署步骤（照做即可）

```bash
# 0) 取代码（纯英文路径；示例为仓库根，具体目录由各机自定）
git clone <仓库地址> hubflow && cd hubflow
git checkout <演示用的 commit / tag>       # 演练回滚时改这一行即可

# 1) Python 环境（任选其一；团队用独立 venv 与其它链路隔离）
python -m venv .venvs/assembly
# Windows: .venvs\assembly\Scripts\activate     Linux: source .venvs/assembly/bin/activate
python -m pip install --upgrade pip
python -m pip install fastapi uvicorn psutil   # 一期接口层 + 监控所需；不引入联网服务

# 2) 自检环境与数据源（不起服务，只打印解析结果）
python work/assembly/traffic.py --check

# 3) 生成演示所需产物（缺哪步就跳过哪步，演示脚本会如实标阻塞）
python work/engine/run.py --network real        # 真网算路 → work/engine/out/real/routes.json
python work/perception/run_chain.py             # 感知链路（需要 work/perception/data/monitor/ 样本导出）
# 孪生链路：python work/twin/run.py --sample    # 可选；生成 work/twin/out/ 样例快照

# 4) 起接口层（演示主进程；另开终端保持）
python work/assembly/traffic.py --port 8000
#    可选：感知服务（感知页视频）
python work/perception/server.py --port 8101
#    可选：前端 remote 模式
cd work/frontend/ui-vue && npm run dev:remote

# 5) 健康检查（应返回 200 + is_simulated: true）
curl -s http://127.0.0.1:8000/api/traffic/meta
python work/assembly/monitor_check.py           # C-7 监控自检（进程/端口/数据/磁盘/持久化）

# 6) 一键演示（C-4；M1-6 用 --rounds 3）——会自动起停接口层
python work/assembly/demo_all.py --rounds 3
#    Windows 也可：powershell -ExecutionPolicy Bypass -File work/assembly/demo_all.ps1 --rounds 3

# 7) 停服务：Ctrl+C（traffic.py / perception server 前台进程）；演示脚本会自己停子进程
```

**启动后确认（30 秒巡检）**：

```bash
python work/assembly/monitor_check.py            # 期望：总体「全部正常」；有警告按提示动作处理
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/api/traffic/segments   # 200
```

## 3. 进程守护（一期：够用即可，不上集群）

一期是单机演示，**不引入 systemd 集群 / 容器编排**；按现场条件三选一：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 前台终端（默认）** | 两个终端分别跑 `traffic.py` 和（可选）`perception/server.py`；演示时保持窗口不关 | 彩排 / 现场演示（最简单，出问题看得见） |
| **B. Windows 任务计划 + 守护脚本** | 任务计划「登录时启动」→ **直接运行接口层** `python work/assembly/traffic.py --port 8000`；失败重启用任务计划的「如果任务失败，重新启动」 | 展厅常开机 |
| **C. Linux systemd（示例）** | 见下方 unit 模板；`Restart=on-failure` + `RestartSec=5` | 若演示机是 Linux |

```ini
# /etc/systemd/system/hubflow-traffic.service  （示例，路径按机器改；一期未启用）
[Unit]
Description=hubflow traffic interface (demo)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/hubflow
ExecStart=/opt/hubflow/.venvs/assembly/bin/python work/assembly/traffic.py --port 8000
Restart=on-failure
RestartSec=5
StandardOutput=append:/opt/hubflow/logs/traffic.out.log
StandardError=append:/opt/hubflow/logs/traffic.err.log

[Install]
WantedBy=multi-user.target
```

> **守护纪律**：① 守护的是**接口层**这一个进程；② 前端 / 感知服务可选、挂了不影响业务接口（页面按降级展示）；
> ③ 守护脚本**不自动改数据 / 不自动复位运行态**（避免把演示态悄悄清掉）；④ 值班人仍要能回答「数据新鲜度 / 当前告警 / 是否降级」；
> ⑤ **`demo_all.py` / `demo_all.ps1` 是演示编排脚本，跑完会自己停掉接口层，不能当守护命令**（Windows 任务计划请按 B 直接跑 `traffic.py`）。

| 日志 | 位置 | 说明 |

## 5. 回滚（演示前必读）

| 场景 | 回滚动作 | 验证 |
|---|---|---|
| 代码 / 接口形状出问题 | `git checkout <上一版 commit>`（或 `git revert <commit>`）→ 重启接口层 | `traffic.py --check` 通过 + `GET /meta` 200 |
| 站点参数 / 阈值异常 | 回滚 `stations/thresholds.json` 等站点包到上一版（**站点包只改配置**，风险最低） | `GET /thresholds` 数值与 `param_version` 对得上 |
| 处置运行态异常（下发 / 回写脏了） | 停服务 → `python work/assembly/traffic.py --reset-state` 或删 `work/assembly/data/dispatch.json` → 重启 | `GET /alerts` 回初始态；审计留 reset 记录 |
| 演示产物异常（路线 / 快照） | 重跑同一输入（`engine real` / 感知链路 / 孪生）；**可回放是硬要求**（TC-13） | 产物 `ts` 是本次运行、requests/段数与上轮一致 |
| 运行态文件损坏 | 按 README §2.2：坏文件自动改名 `*.corrupt-<时间>` 留证后按初始态启动 | 启动日志无写失败；`GET /alerts` 正常 |
| 依赖 / 环境损坏 | 重建 venv → `pip install fastapi uvicorn psutil` → 重跑 `traffic.py --check` | 同上 |

> 回滚**必须留记录**：谁、何时、因为什么、回滚到哪一版（手册 §21.3）。
> 参数 / 模型回滚不得静默：接口层 `GET /thresholds` 的 `changelog` / `param_version` 要能看出来。

## 6. 监控项清单（按手册 §21.2 分层，标一期 / 二期）

> **每条监控都必须有可执行动作**，不做「只显示不报警」的看板。
> 一期可实测项由 [`monitor_check.py`](monitor_check.py) 一条命令采集（`python work/assembly/monitor_check.py`）。

### 6.1 数据层

| 监控项 | 阈值 | 级别 | 一期怎么做 | 动作 |
|---|---|---|---|---|
| 检测断面数据新鲜度 | `data_age_s > 120 s`【待标定】 | 高 | ✅ `monitor_check.py` 按 `data_age_s` 统计陈旧路段（阈值 `--stale-threshold`） | 该路段标「陈旧」、**不进入推荐计算，只展示**（TC-06） |
| 路段数据可用性 | `level=0` / `available=false` / 缺数据 | 高 | ✅ `monitor_check.py` 统计不可用段数；**全部不可用 → fail**，部分不可用 → warn | 页面标「数据不可用」；检查上游产物是否生成 |
| 数据置信度 | `confidence < 0.5`【待标定】 | 中 | ⚠️ 数据字段在场，阈值判定归感知层（一期展示） | 不给强推荐，降级为「仅提示」 |
| 因素数据缺失 | 某因素「未获取」 | 中 | ✅ `GET /factors` 的 `counts` / `injected` 如实为空 | 管理端提示；**不得当作「无影响」** |
| 参数版本过期 | 距上次标定 > 8 周【建议值】 | 中 | ⚠️ `GET /thresholds` 带版本，过期比较属二期 | 提示「参数待更新」 |

### 6.2 服务层

| 监控项 | 阈值 | 级别 | 一期怎么做 | 动作 |
|---|---|---|---|---|
| 接口层进程 / 端口 | 进程不在 / 8000 不 LISTEN | 高 | ✅ `monitor_check.py`（psutil + 端口探测） | 拉起进程（守护）；按 §21.5 处理 |
| 接口可用性 / 时延 | `P95 > 3000 ms`【demo 目标值】 | 中 | ✅ `stress_test.py` 实测 P50/P95（见压测报告）；单次巡检看 `meta` 时延 | 记录并排查；双端降级为只读 |
| 接口 5xx | 出现即异常 | 中 | ✅ `monitor_check.py` 巡检**所有探测端点（含 meta）**的 5xx 数，非 2xx 另计 | 立即看日志；按 §21.5 P1 处置 |
| **数据源降级状态** | 响应头 `X-Traffic-Data-Source` = `stations.baseline` | 中 | ✅ `monitor_check.py` 对 `stations.baseline` 回落**显式告警（warn）**，其余数据源记 ok | 页面按「数据不可用」灰档展示；补跑上游产物 |
| 主循环心跳 | 超 3 个周期未出快照 | 高 | ⚠️ 一期看 `ts` / `data_age_s`；快照产出归孪生主循环（二期守护） | 页面显示「数据暂停」；值班人按 §21.5 处理 |
| 磁盘 / 日志 | 磁盘 > 85%【建议值】 | 中 | ✅ `monitor_check.py` 磁盘使用率 + 日志体积 | 清理 `out/` 与旧产物；归档后重跑 |
| **处置闭环持久化文件** | 不可解析 / 写失败（`PERSIST_FAILED`） | 高 | ✅ `monitor_check.py` 解析 `data/dispatch.json`（schema / 告警数 / 审计数 / 复位次数） | 停写 → 按 README §2.2 坏文件流程处理（改名留证，按初始态启动） |
| 备份任务 | 失败 / 超 24 h 未备份 | 高 | ❌ 二期（一期演示数据全留、可重跑；无生产备份） | 人工介入（§21.3） |

## 7. 一期范围声明（**不越界承诺**）

1. 一期是**单机演示环境**：单进程 Python + 文件快照 + JSON 运行态；**没有**高可用 / 集群 / 容器编排 / 生产数据库；
2. **没有真实用户数据**、没有真实账号与鉴权（服务只绑回环）；**没有真实下发通道**；
3. 视频感知是**样本视频回放**（非本站现场）；数据同化 / 真实摄像头接入属二期；
4. SUMO 安装与孪生主循环只服务其它链路，**本单交付的演示/压测/监控脚本不依赖 SUMO**（真网算路是纯 Python）；
5. 监控只落地 §21.2 中**一期可实测**的数据/服务项；效果、备份、合规留存**如实标二期**，不假装监控；
6. 演示 / 压测数字均为**本机实测**，不构成 SLA 或对外性能承诺；SLA 全部【待标定】（手册 §21.4）。
