### 4.3 ⚠️ 中文路径导致 `image` 模式失败（**已关闭：按方案 A 迁移到纯英文路径，2026-10-10 业主裁定**）

**现象**：`python demo_cli.py image` 报错

```text
OSError: 写出标注图失败: D:\智能体内核流量管理\agentic-traffic-management\traffic-core-mindspore\runs\detect\predict\road.jpg
```

**根因（已隔离验证）**：**OpenCV 的 `imwrite` / `imread` 不支持含中文的绝对路径。**

| 实验 | 结果 |
|---|---|
| `cv2.imwrite('D:/_t_ascii.png', img)` | ✅ True |
| `cv2.imwrite('D:/智能体内核流量管理/_t_cjk.png', img)` | ❌ **False** |
| `cv2.imwrite('runs/detect/_probe_rel.png', img)`（相对路径，CWD 含中文） | ✅ True |
| `cv2.imread(os.path.abspath('image/road.jpg'))`（绝对，含中文） | ❌ **None** |
| `np.fromfile(...) + cv2.imdecode(...)` 绕过 | ✅ OK |

上游代码里 `_next_predict_dir()` 基于 `REPO_ROOT`（由 `__file__` 解析）**必然产出中文绝对路径**，所以 **`image` 模式在本工作区必失败**；`track` / `count` 只用到相对路径，因此不受影响。

**第二个问题（同一处代码）**：`track` / `count` 的 `_write_frames()` **既不 `makedirs` 也不检查 `isOpened()`**——`video_output/` 不存在时 **静默不产出视频文件，但控制台照样打印"轨迹条数: 9"**。实测：删除 `video_output/` 后重跑，命令报成功、目录没生成。**这是"看起来通过、其实没产物"的假通过**，比报错更危险。

**处置裁定（2026-10-10：采用方案 A，已执行）**

| 方案 | 做法 | 代价 |

| **A（推荐）** | 把两个仓库放到**纯英文路径**，如 `D:\work\hubflow` 与 `D:\work\agentic-traffic-management`（仍保持同级） | 一次性搬目录，全员统一；`README` 里的相对路径不受影响 |
| B | 不改路径，改动上游代码：写出改 `cv2.imencode + open(...,'wb')`，读入改 `np.fromfile + cv2.imdecode`，并补 `makedirs` + `isOpened` 检查 | 属上游仓改动，需按流程走；**四处开发都受益** |
