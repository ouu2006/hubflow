# 决策线

> **产出**：`routes.json` —— 推荐路线、备选、离站路线、配额状态
> **消费方**：前端
> **同时负责**：`stations/` 站点包结构、地图 API 接入

## 负责什么

```text
读 segments.json → 路网 + 行程时间函数 → 候选路径
                → 配额租约分配 → routes.json
```

## 核心机制：按剩余容量发号

**不是"给每个人此刻最快的那条路"** —— 那条路会被自己的推荐压垮。做法：

1. **不记身份，只记数量**：维护每个 OD 对、每条候选路径的剩余配额，每次请求消耗一份。**全程不记车、不记人、不记车牌。**
2. **先到先得**：第 2 辆车请求来时 A 路配额已见底 → 引擎自动给 B 路。
3. **配额带租约**：`T_lease = 90 s`，未确认采纳即释放。
4. **周期重算 + 滞回**：每 `ΔT = 60 s` 用**实测流量**（不是发放量）重算；切换路径有 `h = 10%` 滞回。

## 算法四步

| 步 | 做法 | demo 参数 |
|---|---|---|
| ① 候选生成 | K 最短路（路径重叠度 ≤ 0.7） | K = 3 |
| ② 行程时间 | `t = t⁰·[1+α(x/c)^β]` | α = 0.15、β = 4.0【待标定】 |
| ③ 系统最优 | 边际成本近似 `α' = α(1+β)` | — |
| ④ 分配 + 分散 | 增量分配 + Logit 分散 | M = 5、μ = 0.3/min【待标定】 |

**占比上限**：路径级 K≥3 取 0.5、K=2 取 0.7（且两候选耗时差 ≥ 2 min）；路段级 0.75。

## 地图接入（高德 + 百度）

- **主用一家 + 另一家交叉校验**，**不要两家同时在线取数**（道路等级与车道数口径会打架）；
- **坐标系必须转**：站点包统一存 **WGS-84**；与高德转 GCJ-02、与百度转 BD-09。**不转的话车的位置会整体偏一条街**；
- 转换算法**离线内置**，不要每次调在线接口；
- **拉取结果必须落盘**，不要每次运行都调 API。

## 交付标准

- 引擎代码里**不出现任何站点名、坐标、路名硬编码**；
- 同一组起终点**连续请求多次，推荐不集中在单一路线**；
- **备选 ≥2 条**（+ 推荐 1 条 = 合计 ≥3 条方案，与 K=3 候选生成一致；口径见 `docs/数据契约.md`）；
- 只有一条候选时输出 `no_alternative: true` + 原因，**不得为凑数返回等价路径**。

## 站点包位置（2026-10-09 裁定）

**用仓库根目录 `stations/`**，不是 `work/engine/station/`。

理由：站点包是**跨模块共享的配置**——感知线要读 `thresholds.json`（判级阈值）与 `calibration.json`，前端要读 `points.json`（点位渲染）。放在 `work/engine/` 下会让其他位置都得跨目录取，与"每个人只改自己目录"的规则冲突。

**你（决策线）定结构、数据与标注岗填数据。** 结构一旦定下来，就是冻结件，改要提 Issue。

地图拉取的原始数据放共享盘；**转好的站点配置是小文本，进仓库**（`stations/`）。
