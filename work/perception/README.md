> **产出**：`segments.json` —— 每条路段的指标与拥堵等级
> **消费方**：决策引擎、前端
>
> **一期**：数据来自**数字孪生里的虚拟检测器**（不碰视频）。

## 一、两段式路线图

| | **一期（当前）虚拟层** | **二期 真实层** |
|---|---|---|
| 数据来源 | **虚拟检测器**（`work/twin/detector.py`，放在二期摄像头将来的位置） | **真实摄像头视频**（检测 → 跟踪 → 米制轨迹 → 车道归属） |
| 输入形状 | 路段级聚合数：流量 / 平均车速 / 密度 / 排队长度 | 车辆轨迹（像素 → 米制）→ 再聚合成同样的路段级数 |
| 本目录要做的 | **四项指标 → 判级 → `segments` 快照**（指标口径 + `level.py`） | 新增视频感知链路 + 标定 + 误差预算 + 模型微调 |
| 交付判定 | **M1-2**（≥1 条路段 ≥60 个统计点）、**M1-3**（判级连跑 3 次一致） | **M2-1**（点位接入 ≥7 天）、**M2-2**（微调精度）、**M2-3**（判级与人工一致率 ≥85%） |

## 二、一期：虚拟检测器数据 → 四项指标 → 判级

```text
虚拟检测器（路段级聚合数） → 四项指标（流量 / 车速 / 密度 / 排队长度）
                          → 饱和度 x = q / c → 五步判级 → segments.json 快照
```

### 2.1 五步判级（顺序不能换）

| 步 | 做什么 | 判定标准 |
|---|---|---|
| ① **可用性门** | 数据陈旧 / 置信度不足 → **灰色「数据不可用」**，且**不进推荐计算** | `data_age_s` 超限或 `confidence` 低于阈值 |
| ② **硬触发** | 事故封道、违停占道等**直接触发高档**，不看四项指标 | 因素 `factors_applied` 中出现硬触发类因素 |
| ③ **四项并列取最高** | 四项指标各算一档，**取最高档**（不做平均） | 见下表 |
| ④ **因素修正** | 按 `factors_applied` 合成系数修正容量 / 速度 | 合成后不低于原值的 40%【待标定】 |
| ⑤ **时间维防抖** | **升档立即、降档需连续 2 个统计周期** | 同一输入连跑 3 次结果完全一致 |

| 指标 | 字段 | 含义 |
|---|---|---|
| 流量 | `q_vph` | 辆/小时 |
| 平均车速 | `v_kmh` | km/h（相对口径：`v_kmh / v_f_kmh`） |
| 密度 | `k_vpk` | 辆/公里 |
| 排队长度 | `L_q_m` | 米（同时算 `T_d_min` 消散时间） |

> **饱和口径是相对口径**：判级本来就用"**实测速度 ÷ 这条路的畅通速度**"，**不拿主干道的标准去量落客通道**。这是二期"按路段定制参数"能无缝接上的前提（D6）。

### 2.2 `level.py` 的输入输出

| 项 | 内容 |
|---|---|
| 输入 | 检测器聚合数据（`q_vph` / `v_kmh` / `k_vpk` / `L_q_m`）+ 站点包 `thresholds.json`（阈值与权重）+ 当前 `factors_applied` |
| 输出 | `segments.json` 快照（字段见 [`../../docs/数据契约.md`](../../docs/数据契约.md) 第一节） |
| 纪律 | **阈值必须读 `stations/thresholds.json`**，代码里不得写死；换站必须重新标定 |

## 三、二期：真实视频感知（**一期不投入**）

```text
视频帧 → 检测 → 跟踪 → 像素轨迹 → 透视标定 → 米制轨迹 + 车道归属
       → 四项指标（流量 / 车速 / 密度 / 排队长度） → 饱和度 → 四级拥堵等级
```

| 环节 | 做法 | 关键口径 |
|---|---|---|
| **检测与跟踪** | 复用上游仓库已有链路（`agentic-traffic-management/traffic-core-mindspore/core/`） | 上游轨迹输出是 `{track_id: [{"x": px, "y": px, "c": cls}]}` —— **没时间戳、没米制尺度、没车道归属**，这三样要补 |
| **透视标定** | 像素 → 米，单应矩阵（≥4 组控制点，推荐 6–8 组） | 精度留证：重投影误差 ≤ 3 px、尺度误差 ≤ 3% |
| **有效标定带** | 远处 1 像素对应的实际距离太大 | **超出边界的目标只计数量，不计入速度统计** |
| **误差预算** | 标定误差 + 跟踪误差 + 聚合误差逐项列出，给出指标总误差带 | 误差带要能解释"为什么某路段判级会跳" |
| **视觉微调** | 用**车站真实画面**抽帧标注（**≥2000 帧**、绑定版本号）微调，转 `.ckpt` 部署 | 出租车 / 网约车精度 ≥ 0.85、车辆召回 ≥ 85%（M2-2） |
| **按路段重标定** | 每条路段用自己的真实数据定畅通速度、通行能力、各档边界 | 判级与人工判读一致率 ≥ 85%（M2-3） |

### 3.1 二期开工提醒（**两条实测踩坑，届时必须先绕过**）

1. **中文路径**：OpenCV 的 `imwrite` / `imread` **不支持含中文的绝对路径**，`demo_cli.py image` 在本工作区必失败。**先把仓库放到纯英文路径**，或改用 `cv2.imencode` + `open(...,'wb')` / `np.fromfile` + `cv2.imdecode` 绕过；
2. **输出目录不存在时静默失败**：`track` / `count` 的 `_write_frames()` 既不 `makedirs` 也不检查 `isOpened()`——**命令照样打印"轨迹条数: 9"但视频文件根本没生成**。**先建输出目录**，并且**别只信退出码，要检查产物真的在**。

> **二期资产状态**：`weights/mindyolo/yolov8n.ckpt` 已生成并通过前向数值比对（最差相对误差 2.875e-06），MindSpore 链路的检测 / 跟踪 / 越线计数**均已实测跑通**——**证明技术可行，按 D1 一期不再投入**。

## 四、三条最容易踩的坑（**两期都适用，别丢**）

| 坑 | 后果 | 对策 |
|---|---|---|
| **数据缺失被显示成蓝色** | "没数据"被读成"很通畅"，最容易出事 | 数据陈旧或质量不足 → **灰色「数据不可用」**，且**不进推荐计算** |
| **判级降档抖动** | 阈值边界来回跳 | **升档立即、降档需连续 2 个统计周期** |
| **把落客服务停车算成拥堵** | 系统去"疏导"一辆正常落客的车 | 停车拆三类：**排队（算拥堵）/ 落客服务（不算）/ 违停（算事件）** |

> 第一条对前端是硬要求（**绝不显示成蓝色**），对判级是硬要求（**不可用就走灰色分支**）。**两处都要有。**

## 五、交付标准（一期）

- **M1-2**：至少一条路段能产出平均车速与排队长度的**时间序列**，**≥ 60 个统计点**；
- **M1-3**：同一输入连续跑三次，**判级结果完全一致**，且**至少覆盖两个等级**；
- **TC-01**：虚拟检测器 → 指标 → 判级**可复现**，**上报周期可配置并生效**；
- **TC-16**：多因素注入后，受影响路段 `factors_applied` 出现，**等级 / 耗时变化方向正确**，未受影响路段不变。
