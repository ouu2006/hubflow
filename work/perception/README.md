# 感知线

> **产出**：`segments.json` —— 每条路段的指标与拥堵等级
> **消费方**：决策线、前端

## 负责什么

```text
视频帧 → 检测 → 跟踪 → 像素轨迹 → 透视标定 → 米制轨迹 + 车道归属
       → 四项指标（流量 / 车速 / 密度 / 排队长度） → 饱和度 → 四级拥堵等级
```

## 怎么做

1. **检测与跟踪**：直接用上游仓库已有的代码链路（`agentic-traffic-management/traffic-core-mindspore/core/`）。
   上游代码的轨迹输出是 `{track_id: [{"x": px, "y": px, "c": cls}]}` —— **没时间戳、没米制尺度、没车道归属**，这三样要补上。
2. **透视标定**：像素 → 米。单应矩阵（≥4 组控制点，推荐 6–8 组），精度留证（重投影误差 ≤ 3 px、尺度误差 ≤ 3%）。
3. **有效标定带**：远处 1 像素对应的实际距离太大，**超出边界的目标只计数量，不计入速度统计**。
4. **四项指标 → 判级**：五步流程（可用性门 → 硬触发 → 四项并列取最高档 → 情景系数 → 时间维防抖），完整规格见 [`docs/技术方案与实施手册.md`](../../docs/技术方案与实施手册.md) 第 6 章。

## 三条最容易踩的坑

| 坑 | 后果 | 对策 |
|---|---|---|
| **数据缺失被显示成蓝色** | "没数据"被读成"很通畅"，最容易出事 | 数据陈旧或质量不足 → **灰色「数据不可用」**，且不进推荐计算 |
| **判级降档抖动** | 阈值边界来回跳 | 升档立即、降档需连续 2 个统计周期 |
| **把落客服务停车算成拥堵** | 系统去"疏导"一辆正常落客的车 | 停车拆三类：排队（算拥堵）/ 落客服务（不算）/ 违停（算事件） |

## 交付标准

- 同一输入连续跑三次，判级结果**完全一致**，且至少覆盖两个等级；
- 至少一条路段能产出平均车速与排队长度的**时间序列**（帧数 ≥ 60）。
