| 本目录要做的 | **标定（`calib.py`）+ 米制轨迹 → 四项指标（`metrics.py`）→ 判级（`level.py`，归开发B）** | **四项指标（`metrics.py`）→ 判级（`level.py`，归开发B）** | **重做标定**（现场控制点实测），字段与下游一行不改 |
| 交付判定 | **M1-9**（标定控制点 ≥4 组、重投影误差 ≤3 px【demo 目标值】、至少 1 条路段产出指标）、**TC-19**（两条链路并存可对比）、**M1-10 / TC-20**（边界断面实测经 `calibrator` 回灌给孪生） | **M1-2**（≥1 条路段 ≥60 个统计点）、**TC-01**（可复现、上报周期可配置）、**M1-10**（同化回灌的输入侧） | **M2-1**（点位接入 ≥7 天）、**M2-2**（微调精度）、**M2-3**（判级与人工一致率 ≥85%）、**M2-9**（全部边界断面在线闭环 + 熔断） |

## 二、一期 · 视频链路：样本视频 → 标定 → 四项指标 → 判级

```text
6 段真实样本视频 → 检测 → 跟踪 → 像素轨迹（补时间戳）
                 → 透视标定（stations/calibration.json，控制点由池·V 拾取）
                 → 米制轨迹 + 车道归属 → 四项指标（流量 / 车速 / 密度 / 排队长度，`metrics.py`）
                 → 饱和度 x = q / c → 五步判级（`level.py`，归开发B）→ segments.json 快照（source: "video"）
```

| 环节 | 做法 | 关键口径 |
|---|---|---|
| **检测与跟踪** | 复用上游仓库已有链路（`agentic-traffic-management/traffic-core-mindspore/core/`） | 上游轨迹输出是 `{track_id: [{"x": px, "y": px, "c": cls}]}` —— **没时间戳、没米制尺度、没车道归属**，这三样要补 |
| **透视标定** | 像素 → 米，单应矩阵（OpenCV `findHomography`，DLT + RANSAC）；**控制点 ≥4 组，推荐 6–8 组**（由 **池·V 拾取**——系列 V 的控制点拾取任务：停止线两端、车道线交点、斑马线角点、导流线折点） | 精度留证：重投影误差 **≤ 3 px**【demo 目标值】、尺度误差 **≤ 3%**【demo 目标值】 |
| **有效标定带** | 远处 1 像素对应的实际距离太大 | 远边界取"1 像素对应实际距离 ≤ 0.5 m"；**超出边界的目标只计车辆数（密度、流量），不计入速度统计** |
| **误差预算** | 标定误差 + 跟踪误差 + 聚合误差逐项列出，给出指标总误差带 | 误差带要能解释"为什么某路段判级会跳" |
| **口径纪律** | 视频是**真实拍摄的样本视频，但不是肇庆东站现场** | 对外一律标"**演示数据（模拟）**"；**可以讲**"视频识别正在算路段拥堵"、"MindSpore 链路已验证"，**不得**说成"现场实测"，**不得**讲"昇腾部署已验证" |
| **回灌给孪生** | **边界断面**（`points.json` 里 `role: "boundary"`）的实测**流量 + 车速**，每 **60 s** 通过 SUMO `calibrator` 回灌给孪生的边界来车（**站前内部路段不灌**） | 回灌值**先落盘再喂**；带门控（`confidence < 0.6`【待标定】或 `data_age_s > 120 s` → 停灌并留日志）；见 [`../twin/README.md`](../twin/README.md) 第九节、**M1-10 / TC-20** |

### 2.1 一期 · 孪生链路：虚拟检测器数据 → 同一套四项指标 → 判级

```text
虚拟检测器（路段级聚合数） → 四项指标（流量 / 车速 / 密度 / 排队长度）
                          → 饱和度 x = q / c → 五步判级 → segments.json 快照（source: "twin"）
```

> **两条链路只有 `source` 不同，其余字段逐字段一致。** 孪生链路的输出还用来**被视频实测标定**（到达流率、`v_f`、`s₀`、排队阈值、服务时长，见 [`../twin/README.md`](../twin/README.md) 与手册第 10.13 节）：**先落盘再喂、只标边界不进中间输出**。

> **数据同化（视频链路 → 孪生，手册 10.14）**：视频链路在 **`role: "boundary"` 的边界断面**测到的**流量与车速**，会每 **60 s** 通过 SUMO `calibrator` / TraCI `calibrator.setFlow` **回灌给孪生的边界来车**——"给孪生接一只真实的眼睛"。**这是标定（10.13，定参数）之外的持续注入（10.14，喂输入），两件事别混。**
> **分层原则（最容易做错）**：**只灌围栏外 → 站前的上游边界断面；站前内部路段（落客通道 / 候客区 / 离站方向）一律不灌**——否则孪生变成"录像回放"，推荐再也改变不了路况，"同一输入跑三遍只切推荐"的对照实验失效（**TC-20 第②项**专验）。详见 [`../twin/README.md`](../twin/README.md) 第九节。
> **口径不变**：回灌值是**样本视频**测出来的、**非本站现场**；孪生由此算出的全部数值**仍是"演示数据（模拟）"**，**不得**因为"喂了实测"就宣称成实测结果。

### 2.2 五步判级（顺序不能换，**两条链路共用**）

> **写手**：本节的判级逻辑实现在 `level.py`，由**开发B** 写（开发A 不碰）；开发A 负责把四项指标 `metrics.py` 按上游字段算出来交给它。

| 步 | 做什么 | 判定标准 |
|---|---|---|
| ① **可用性门** | 数据陈旧 / 置信度不足 → **灰色「数据不可用」**，且**不进推荐计算** | `data_age_s` 超限或 `confidence` 低于阈值 |
| ② **硬触发** | 事故封道、违停占道等**直接触发高档**，不看四项指标 | 因素 `factors_applied` 中出现硬触发类因素 |
| ③ **四项并列取最高** | 四项指标各算一档，**取最高档**（不做平均） | 见下表 |
| ④ **因素修正** | 按 `factors_applied` 合成系数修正容量 / 速度 | 合成后不低于原值的 40%【待标定】 |
| ⑤ **时间维防抖** | **升档立即、降档需连续 2 个统计周期** | 同一输入连跑 3 次结果完全一致 |

| 指标 | 字段 | 含义 |
|---|---|---|
| 流量 | `q_vph` | 辆/小时 |
| 平均车速 | `v_kmh` | km/h（相对口径：`v_kmh / v_f_kmh`） |
| 密度 | `k_vpk` | 辆/公里 |
| 排队长度 | `L_q_m` | 米（同时算 `T_d_min` 消散时间） |

> **饱和口径是相对口径**：判级本来就用"**实测速度 ÷ 这条路的畅通速度**"，**不拿主干道的标准去量落客通道**。这是二期"按路段定制参数"能无缝接上的前提（D6）。

## 三、二期：现场实时流（**换源 + 重做标定 + 微调**）

```text
现场实时摄像头流 → 检测 → 跟踪 → 像素轨迹 → 透视标定（现场控制点实测，重做 calibration.json）
                 → 米制轨迹 + 车道归属 → 四项指标 → 饱和度 → 四级拥堵等级
```

| 环节 | 做法 | 关键口径 |
|---|---|---|
| **换源** | 6 段离线样本视频 → **现场实时摄像头流**；点位由池·S 现场订正（踏勘任务） | `source` **仍是 `"video"`**，**下游字段与代码一行不改**；孪生链路**保留为对照基线**（手册 18.9） |
| **重做标定** | 现场控制点实测（不再用"标准车道宽 3.5 m"推算） | 重出误差预算；重投影误差与尺度误差按同一门槛复验 |
| **视觉微调** | 用**车站真实画面**抽帧标注（**≥2000 帧**、绑定版本号）微调，转 `.ckpt` 部署 | 出租车 / 网约车精度 ≥ 0.85、车辆召回 ≥ 85%（M2-2） |
| **按路段重标定** | 每条路段用自己的真实数据定畅通速度、通行能力、各档边界 | 判级与人工判读一致率 ≥ 85%（M2-3） |

## 四、三条最容易踩的坑（**三条链路都适用，别丢**）

| 坑 | 后果 | 对策 |
|---|---|---|
| **数据缺失被显示成蓝色** | "没数据"被读成"很通畅"，最容易出事 | 数据陈旧或质量不足 → **灰色「数据不可用」**，且**不进推荐计算** |
| **判级降档抖动** | 阈值边界来回跳 | **升档立即、降档需连续 2 个统计周期** |
| **把落客服务停车算成拥堵** | 系统去"疏导"一辆正常落客的车 | 停车拆三类：**排队（算拥堵）/ 落客服务（不算）/ 违停（算事件）** |

> 第一条对前端是硬要求（**绝不显示成蓝色**），对判级是硬要求（**不可用就走灰色分支**）。**两处都要有。**

## 五、交付标准（一期）

> **归属**：本节的**标定与四项指标**条目（**M1-2** / **M1-9** / **TC-01** / **TC-19** / **M1-10 / TC-20**）归**开发A**（`calib.py` / `metrics.py`）；**判级**条目（**M1-3**）归**开发B**（`level.py`）；**TC-16** 由开发A 出指标、开发B 出判级，两人共同举证。

- **M1-2**：**视频链路与孪生链路各至少 1 条路段**产出平均车速与排队长度的**时间序列**，**≥ 60 个统计点**；
- **M1-3**：同一输入连续跑三次，**判级结果完全一致**，且**至少覆盖两个等级**；
- **M1-9**：**视频链路（YOLO）真的在算路段**——6 段样本视频完成透视标定（控制点 ≥4 组、**重投影误差 ≤ 3 px**【demo 目标值】），至少 1 条路段产出流量 / 车速 / 排队时序（`source = "video"`），**与人工抽查方向一致**；
- **TC-01**：链路 → 指标 → 判级**可复现**，**上报周期可配置并生效**；
- **TC-16**：多因素注入后，受影响路段 `factors_applied` 出现，**等级 / 耗时变化方向正确**，未受影响路段不变；
- **TC-19**：**两条链路并存且可对比**——都产出 `segments`（`source` 分别为 `"video"` / `"twin"`）、管理端**可并排展示**、**同一段样本视频跑两遍结果一致**、**两者偏差写进自测报告**（允许不同，不要求相等）；
- **M1-10 / TC-20**：**数据同化生效且不钉死下游**——视频链路在**边界断面**（`role: "boundary"`）的实测流量 / 车速每 60 s 经 `calibrator` 回灌给孪生；判定：① 边界断面**孪生流量与视频实测偏差 ≤ 15%**【待标定】、**平均车速偏差 ≤ 20%**【待标定】；② **站前内部路段仍能响应推荐**（开 / 关推荐时内部路段指标出现差异）；③ 关闭同化后回到默认需求；④ 门控生效（`confidence` 压到 0.6 以下或 `data_age` 抬过 120 s → 停止回灌且日志可见）。**内部路段一个都不许挂 `calibrator`**。
