# work/frontend/app-html · 司机端 App 页面试作（单文件 HTML）

> **本目录是一次「页面试作」**：司机端 App 的前端**先用单文件 HTML 顶替**，把"**页面长什么样、点哪里、数据从哪来**"三件事先定死，等鸿蒙工具链就位后照搬成 ArkTS（[IKLLX9](https://gitee.com/ozxowx/hubflow/issues/IKLLX9)）。
>
> ⚠️ **不是最终交付。最终交付是鸿蒙 App**（`work/frontend/harmony/`）。本目录**不写 ArkTS、不装工具链、不碰 harmony/**。

- **对应 Issue**：[IKLX9B](https://gitee.com/ozxowx/hubflow/issues/IKLX9B)（IKLX5Y 的后续单）
- **几何来源**：站点包 Z（[IKLX5Y](https://gitee.com/ozxowx/hubflow/issues/IKLX5Y) 的真 OSM 路网，21 段 / 6 路摄像头）

## 一、怎么打开

**双击 `index.html` 即可**——不需要构建、不需要装依赖、不需要起服务、**不请求任何外部网络**（地图库与底图数据都在目录内）。

> 若浏览器对 `file://` 下的 `<script src>` 有限制（个别配置会拦本地脚本），在仓库根跑一句静态服务即可：
> `python -m http.server 8123 --bind 127.0.0.1`（然后打开 `http://127.0.0.1:8123/work/frontend/app-html/index.html`）。

## 二、目录里有什么

| 路径 | 是什么 |

### 重新生成数据产物

```bash
python work/frontend/app-html/build_data.py            # 从站点包 Z 重抽
python work/frontend/app-html/build_data.py --check    # 只比对，不写（应输出"逐字节一致"）
```

`build_data.py` 只做「抽取 + 打包」：**段 id / 折线 / 等级 / 摄像头全部照抄站点包 Z**，它自己不造段划分、不造指标。

> ⚠️ **前置依赖**：它的默认输入是 `work/frontend/ui-vue/src/station-packs/stationZ.network.ts` + `stationZ.ts`
> —— 这两个文件是 **IKLX5Y 的产物**。`stationZ.*` 还没合进 main 时，在本分支直接跑会提示读不到；
> 两种办法：① 切到含 `stationZ.*` 的分支再跑；② 用 `--network-ts` / `--pack-ts` 指到实际路径。
>
> **本目录 `data/` 下三份产物已经生成好并入库**，所以**双击 `index.html` 不需要跑这个脚本**。

## 三、版式：按常规导航 App

- **手机壳**：390 × 844 固定视口，页面居中，**不出横向滚动条**。
- **地图当首页**（`#map` 铺满壳内）。
- **底部标签栏 5 项**：地图 / 当前建议 / 落客候客 / 离站路线 / 我的行程——后四项按 C-3 的页面口径**做壳**（标题 + 关键字段，内容从简）。
- 顶部导航卡（转向图标 + 距离 + 路名 + 当前路段等级）保留，改造成手机导航卡的样子。
- **不做花哨动效**（手册风险表第 12 条同口径）。

## 四、地图页：路线段按站点包 Z 上色

**段划分一律用站点包 Z（`SZ-01` … `SZ-21`，21 段）**，上色规则照抄 IKLX5Y：

| 情形 | 画法 |
|---|---|
| 有摄像头 + 有数据 | 按 `level` 四级色（线宽 5.5，不透明度 0.96） |
| 有摄像头但无数据 | 灰（`#8B8B8B`，粗）——**TC-11** |
| **无摄像头** | 中性灰**轮廓**（同一个灰，线宽 1.8，不透明度 0.34）——"这段没监控" |

> 本站实际分布：**5 段上色**（`SZ-01` 3 级 / `SZ-03` 2 级 / `SZ-05` 2 级 / `SZ-07` 1 级 / `SZ-12` 4 级）、**16 段灰轮廓**；6 路摄像头都落在有数据的那 5 段上，"有摄像头但无数据 → 灰"这一档本站未出现（图例里写明）。

- **每段可查摄像头数**：点路段弹信息卡，显示等级 / 拥挤指数 / 链路 / **摄像头几路（没有的如实显示 0 路）** / 指标出处。
- **点摄像头**弹通道卡：通道 `source` / 所属路段 / **视频源"未接入视频源 · 本期留空"**（本批 6 路**全部没有视频源**，如实显示）。
- **底图**：水系 / 绿地 / 背景路 / 路口全部来自 `data/map-shapes.json`（**脱网**）；图上只画**站点包 Z 的 21 段**，不另画一套路网。
- **OSM 署名**：图角「© OpenStreetMap contributors」链到 <https://www.openstreetmap.org/copyright>（条款核实 E-11 / E-13）。

### 「全览」保留

右下角悬浮按钮，点击把整张站点包 Z 路网框进屏幕（`fitBounds` 到 21 段的包围盒），**俯仰角归零、跟随关闭**。
自检口：`window.HUBFLOW_APP.segmentsInView().length` 在全览后应等于 **21**。

### 不做「生成路线」

原始 demo 里的 **✏️绘制 / ✓生成路线 / ✕清除** 三个按钮，以及那段直连 `router.project-osrm.org` 的 `fetch`，**已连根拔掉**。

**为什么**：**路线由后台按路段拥堵推算**，App 只负责**把起点终点发过去、把路线画出来**。客户端自己算路线与这条口径冲突，演示现场也不该出现这种外部请求。

**本单只留接口位**：起点 / 终点两个下拉（21 段可选）+ 一个「请求路线」按钮。

- 按钮**本单不发真请求**；用**站点包 Z 的 `recommend`**（`arrival_segments` / `departure_segments` / `alternatives` / `why`）当**后台返回的替身**；
- 按钮下方**如实标注**：「路线由后台按路段拥堵推算 · 本单只留接口位（不发真请求）」；
- **响应字段名的目标形状是 [`docs/数据契约.md`](../../../docs/数据契约.md) §二（`routes`）**；**不改契约、不加字段**。
  > ⚠️ **注意替身与契约的形状差异**（下一棒接手时先看这一条）：页面现在直接读的是**站点包 recommend 的扁平字段**
  > （`arrival_segments` / `departure_segments` / `alternatives[].segments`），而契约 §二 是**嵌套的**
  > （`arrival_route.segments` / `alternatives[].path` / `session_id`）。**换真后台不是只换 base，
  > 还要加一层字段适配**——这一步留给接后台的那一棒，**本单不做**（本单的产物是版式与交互口径）。
  > 另外 C-3 要求备选 ≥2 条，而站点包 Z 只给 1 条：**缺口如实登记在页面上，本单不编造**。

| 项 | 在页面上的落点 |

| **`is_simulated`** | 数据产物 `network.json` / `map-shapes.json` 顶层各一个 `true`；「当前建议」页"数据来源"卡里也写明 |
| **OSM 署名** | 图角超链接（见上） |
| **三重编码** | 四级**颜色 + 图标（○ ◇ ▲ ■）+ 文字**同时出现；图例与信息卡都带图标 |
| **告知文案** | 「当前建议」与「离站路线」页各一句：**该建议基于当前路况，可能随流量变化** |
| **应急态** | 「当前建议」页的**演示开关**（明确标注"不是真实应急"）→ 停下路线引导，替换为「**请服从现场指挥**」（TC-05） |
| **口径红线** | 页面**不出现**「实测 / 实时 / 现场」（唯一的"现场"在应急文案「请服从现场指挥」里——那是手册原文，与被禁的"实测/实时/现场"表述无关）；不把路况说成 SUMO 输出或真实画面 |
| **不做定位** | 车辆位置用站点包 Z 自己的演示位置（`recommend.location_segment_id` + `location_offset_m`）；**不跨包去取别包的演示车**（跨站取车会出现"别站的车画在本站图上"；包 A 已于 IKM4XX 删除） |

## 六、自检口（举证 / 回归用）

页面挂了一个 `window.HUBFLOW_APP`，**页面本身不依赖它**：

```js
HUBFLOW_APP.segmentsInView()   // 当前视口里可见的段 id 数组 —— 全览后应为 21 条
HUBFLOW_APP.paintOf()          // 每段当前画出来的颜色 / 线宽（对站点包 Z 的上色规则）
HUBFLOW_APP.cameraMarkers()    // 摄像头标记数（6）
HUBFLOW_APP.overview()         // 等价于点「全览」
HUBFLOW_APP.map                // MapLibre 实例（调试用）
```

**已实测（2026-10-15，Chrome / 1440×900）**：21 段全部渲染、5 段上色 / 16 段灰、6 个摄像头标记、全览后 21 段全在画面内、应急态下车与路线离开画面且不会被下一帧写回、页面无字面 Markdown 星号、页面无任何外部网络请求（`document.scripts` 与 `link` 全部指向 `vendor/` 与 `data/`）。

## 八、已知限制（如实记录）

1. **这是试作，不是最终形态**：写法都是"浏览器里成立"的（单文件 + 全局变量），搬到鸿蒙 ArkTS 时要重写；**本单的产物是版式与交互口径**。
2. **地图库与底图都在本地**，但 **MapLibre 是 WebGL 渲**——极老的浏览器 / 关掉硬件加速时地图区会空白（此时页面仍不白屏：导航卡、图例、起终点、标签栏都在）。
3. **备选路线只有 1 条**（站点包 Z 现状），而 C-3 要求 ≥2 条——**缺口如实登记，本单不编造第二条**（补齐在站点包 / IKLLX9 那条线）。
4. **"落客 / 候客"页的候客等待、点位 id**：站点包 Z 未带，页面**不编造**，如实写"本包未带"。
5. **`preserveDrawingBuffer: true`** 是为截图举证开的（默认 false 时 WebGL 内容可能截不到）；它牺牲一点性能，演示无感。
