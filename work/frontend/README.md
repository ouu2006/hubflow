### 3.1 一期：**绑定演示车**

| 项 | 口径 |
|---|---|
| 数据来源 | `GET /api/traffic/vehicles`（读 `vehicles.json`，**孪生内部数据**） |
| 绑定规则 | App 一期**只绑一辆"演示车"**——`is_demo_bound: true` 的那一辆，**同一时刻最多一辆** |
| 为什么要绑 | 一期车辆就在孪生里，**没有真实定位可上报**；绑一辆车让 App 能显示"它的位置、推荐路线、备选、离站路线"，证明**双端同源**（M1-5） |
| 位置从哪来 | **后端直接给**（孪生真值），App **不做任何定位请求** |
| 口径纪律 | 一期 App **不得**声称"已接入真实定位"；`GET /api/traffic/vehicles` **二期下线** |

### 3.2 二期：真实定位上报（**一期只留接口位，不实现**）

| 项 | 口径 |
|---|---|
| 上报频率 | 进入站前围栏后 **每 5–10 秒上报一次** |
| 权限 | **用户主动同意**才开启定位；**首次进入围栏时请求**，不在启动时弹 |
| 上报内容 | 位置（统一转 **WGS-84**）+ 航向 + 时间戳 + `session_id`（**匿名会话号，不含身份**） |
| 后端处理 | `POST /api/traffic/locate` → 地图匹配 → 路段 + 路段内位置 + `match_confidence` |
| 低置信度 | `match_confidence < 0.6`【待标定】时**不用于重新规划**，提示"定位不稳定，请确认所在道路" |
| 隐私告知文案（**必须原样出现**） | 「**本 App 仅在您进入站前区域后使用您的定位，用于判断您所在的道路并为您匹配路线。定位信息只用于您本人的本次行程，行程结束后即删除；不会记录您的车牌或身份，也不会与路侧摄像头数据关联。您可随时在设置中关闭定位。**」 |
| 拒绝定位 → 降级 | **流程不中断**：降级为「**手动选所在道路 / 只看路况**」，仍可看推荐与路况，**不反复弹窗**（TC-05） |
| 存储 | **只保留本次会话，行程结束即删**；不入库、不给其他司机看 |

## 四、三条硬性要求（**两期都适用**）

1. **三重编码**：**颜色 + 图标 + 文字必须同时出现**，关掉颜色也要能区分四级。缺一视为不通过。
2. **数据不可用显示灰色**，**绝不显示成蓝色**——"没数据"不能被读成"很通畅"。一期判级的可用性门会输出"不可用"，页面必须有这个分支。
3. **不强制、不反复弹窗**；**应急状态下停止路线引导**，替换为"请服从现场指挥"（优先级高于一切推荐）。

### 9.1 新页 `/heat` 拥挤度热力

| 项 | 实现 |
|---|---|
| 视图切换 | **四级视图 ↔ 拥挤指数视图**(`NetMap` 新增 `mode` prop;`/heat` 页头切换,`aria-pressed` 标注) |
| 图例 | 四级视图沿用四级三重编码图例;指数视图给**色阶 + 档位刻度(0/25/50/75/100)+ 灰档说明** |
| 更新时间戳 | 页头「更新时间戳(快照时间)」+ 图例内 + 页脚,**三处必现**(手册 §:1858) |
| 辅助排序 | 指数视图下路段列表**按 `ci` 降序**并显示 `ci` 值(手册 §6.5 第 1 条:CI 可用于辅助排序) |
| 热力渲染 | 路段级色块 + 强度晕染(blur 层,强度随 `ci` 单调增);**不做断面间无标注内插** |
| 数据不可用 | 缺 `ci` 或数据陈旧 → **灰色 + 「不可用」**(TC-11),**绝不落进通配色** |

**三条口径(实现方式申报)**:

1. **CI 色阶复用四级色值,不自造第五套颜色语义**——锚点取手册 §6.2 的 `#1E6FD9 → #F2B705 → #E8760C → #C62828`(档心为锚点、档间线性过渡),灰 `#8C8C8C` 仍只表示"数据不可用"。
2. **档位边界(0/25/50/75/100)是展示口径**——文档未定档,图例逐条写明;判级一律以 `level` 为准。
3. **CI 只用于展示与辅助排序,不得作为判级依据**(手册 §6.5 第 1 条)——页脚、图例、列表三处标注;两种视图同页互证,冲突时以四级为准。

> 真实权重与档位的来源是 `stations/thresholds.json`(**唯一写手开发B**),前端**不新造阈值、不把权重写死**。

5. **页签 / 站点 / 快照时间进顶栏**:`document.title` 仍由 `router.afterEach` 写;页面标题口径不变(`meta.title`)。
6. **时间展示统一走 `formatStamp` / `formatClock`**(`shared/traffic.ts`):此前若直接插值 ISO 串会在页面出现 `2026-10-12T16:23:54+08:00`;
   且 `slice` 式截取在接口返回 UTC(`Z`)时会错显时区,故统一改为 `Date` 解析后本地化。
7. **`vehicles` 端点是二期下线项**,本次未改动其形状;决策/态势页只用到其计数与采纳率,**计数来自 `overview`,不直接依赖 vehicles 条数**。
8. **一屏密度**:四页按 1440×900 设计,主体三栏各自独立滚动(`.td-scroll`)。三栏**都要有**栏内 `overflow-y:auto`——
   PR #70 曾因左栏漏加导致「按钮可见但点不到」,本次三栏都补齐。
9. **告警三字段随读带回**:`/api/traffic/alerts` 元素新增 `dispatch_ratio_pct`(下发比例),与既有 `channels` / `dispatch_at` / `writeback`
   一起构成**下发 + 回写留痕**——刷新页面后前端据此还原派发回执(不再是"刷新即丢")。后端实现时须把这三组字段落库并随读返回。
10. **告警写入端点新增校验与状态约束**:`plan/dispatch` / `plan/ack` 现在校验告警存在(404 `ALERT_NOT_FOUND`)、
    `segment_id` 与告警一致(400 `ALERT_SEGMENT_MISMATCH`)、`result` 必须是四选一(400 `ACK_INVALID`)、
    终态不可再动(409 `ALERT_TERMINAL`)、**回写必须有派发回执在前**(409 `ACK_NO_DISPATCH`,TC-07 闭环顺序)。
    新增 `POST /api/traffic/alerts/reset` 清演示态;后端实现需保持同一套状态机与错误码。
11. **detections 读取失败与"未导出/无检出"三分**:感知页把「未导出(服务端无该路)」「读取失败(接口报错)」「无检出(数据为空)」
    分开显示,失败一律标红并进页头提示条,**不静默成"本帧无检出"**;三处合计口径同步排除失败路并注明。后端联调时不要用空数组代替错误响应。

## 十一、站点包层:第二个站接入,实测手册 §8.4(2026-10-12)

**背景**:业主拿一张**凭空造的「一环五射」示意路网**(5 条分支都通往站外,目的是有一套完整可演示的线路)
当"第二个站",要求接进管理端看效果。这正好是对手册 **§8.4 判定标准**——"换一个站只新增 / 替换配置文件
即可接入,**不改引擎代码**"——的一次实测。

### 11.1 结论先说:接入前**换不了站**,重构之后才换得了

接入这件事没能"只加一份配置"就完成。原因是接入前的管理端把**站名、路网几何、路段基线、断面编号、
告警剧本、分流建议、感知通道映射**全写死在代码里(`shared/demoNetwork.ts` / `mock/traffic.ts` /
`shared/demoDecision.ts` / `perception/components/channels.ts`)——它只有一份站点的数据,物理上换不了站。
把二站直接喂进去会得到自相矛盾的画面:画二站的路、报一站的名与基线。

本次因此做了一件**一次性的重构**,把"哪一站"这件事抽成站点包层:

| 文件 | 作用 |
|---|---|
| `src/station-packs/types.ts` | 站点包类型(`StationPack`):站名 + 路网几何 + 断面 + 点位 + 路段基线 + 告警剧本 + 分流建议 + 感知通道 + 同化记录 + 桥接开关 |
| `src/station-packs/index.ts` | 包选择器(`activePack()` / `setActivePackKey()`);浏览器与 vite mock 中间件**共用同一个键**,避免"页面画二站、mock 报一站" |
| `src/station-packs/stationA.ts` | 包 A = 肇庆东站示例路网(原写死在代码里的那份,原样搬进来) |
| `src/station-packs/stationB.ts` + `stationB.network.ts` | 包 B = 第二个站(「一环五射」虚构示范站);`.network.ts` 是 SUMO 产物生成的几何/基线,勿手改 |
| `src/shared/demoNetwork.ts`(改) | 从"自带数据"退化为**只读门面**:页面与 mock 的调用名不变,数据从当前包取(**惰性**读——包键在挂载前才注入) |
| `src/mock/traffic.ts`(改) | 路段基线 / 合成车 / 断面 / 告警 / 双源覆盖 / 站点元信息全部改从包读,文件里不再有"某个站才有的"常量 |
| `src/shared/demoDecision.ts`、`perception/components/channels.ts`(改) | 分流建议、通道↔路段映射改从包读(与站点无关的阈值 / 渠道枚举 / 通道目录仍留在原处) |
| `src/components/AppShell.vue` + 四页(改) | 站名默认值取当前包,拿到 `/meta` 后由 `meta.station.name` 覆盖——四页同一口径 |

**重构之后**,再加第三个站才是"新增一个包 + 一行环境变量"。也就是说:判定标准成立的前提是
**先把与站点无关的部分与站点包分开**;这条实测结论比"能换站"本身更值得记。

### 13.3 新增接口面（前端已接、mock 已实现、**后端待实现**）

| 端点 | 方法 | 用途 | 前端调用点 |
|---|---|---|---|
| `/api/traffic/context` | GET | 环境上下文：天气 / 时间 + 折算出的因素（F01 天气 / F02 昼夜 / F03 列车到发 / F10 时段日历） | 感知层环境条、决策可视化 |
| `/api/traffic/scenario` | POST | **场景注入**（天气 / 时段 / 需求倍率）→ 返回注入前后判级对照 | 决策可视化「可调控」 |
| `/api/traffic/scenario/reset` | POST | 清场景注入（与 `factors/reset` 同口径） | 决策可视化 |

**口径铁律（违反即不通过）**：

1. **天气 / 时段是编造的演示值**——真实气象与列车数据拿不到，页面一律标「演示数据（模拟）」，**不出现"实测 / 实时 / 现场"**；字段口径对齐手册第 19 章因素登记表（F01/F02/F03/F10）。
2. **场景注入 ≠ 人工置位**——手册 §:2222 规定管理端人工置位口子**只有 F07 / F08 / F11**（事故 / 管制 / 大型活动）；环境侧（F01/F02/F03/F10）走 `POST /api/traffic/scenario`，**端点分开、文案分开**，页面明写"是两个口子"。
3. **默认态不碰站点包基线**——站点包声明的那套天气是**观测**（包 A 声明大雨，其 SEG-003 / SEG-007 基线里本就烘了 F01 大雨 ×0.75）。`applyFactors` 只在**注入过**（`scenarioState` 非空）时才剔除包里烘入的环境因素再重放；未注入时**逐位不动**，避免把整张基线推高一档（实测踩过：x 0.54→0.71、level 2→3，QA 基线全漂）。
4. **注入前后对照取未抖动口径**——抖动每轮随机，拿抖动后的快照当对照会把噪声算成"注入效果"；对照由 mock 侧 `levelsAfterFactors()` 算，前端不算。
5. **决策可视化的演算不是模型推理**——阈值档位来自 `GET /api/traffic/thresholds`（前端不自造），页面明写"演示口径 · `level.py` 未实现"。
6. **CI 只用于展示与辅助排序，不得作为判级依据**（手册 §6.5 第 1 条）——大屏页脚、热力图例、指数排行三处标注。
