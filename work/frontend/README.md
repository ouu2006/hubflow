### 3.1 一期：**绑定演示车**

| 项 | 口径 |
|---|---|
| 数据来源 | `GET /api/traffic/vehicles`（读 `vehicles.json`，**孪生内部数据**） |
| 绑定规则 | App 一期**只绑一辆"演示车"**——`is_demo_bound: true` 的那一辆，**同一时刻最多一辆** |
| 为什么要绑 | 一期车辆就在孪生里，**没有真实定位可上报**；绑一辆车让 App 能显示"它的位置、推荐路线、备选、离站路线"，证明**双端同源**（M1-5） |
| 位置从哪来 | **后端直接给**（孪生真值），App **不做任何定位请求** |
| 口径纪律 | 一期 App **不得**声称"已接入真实定位"；`GET /api/traffic/vehicles` **二期下线** |

### 3.2 二期：真实定位上报（**一期只留接口位，不实现**）

| 项 | 口径 |
|---|---|
| 上报频率 | 进入站前围栏后 **每 5–10 秒上报一次** |
| 权限 | **用户主动同意**才开启定位；**首次进入围栏时请求**，不在启动时弹 |
| 上报内容 | 位置（统一转 **WGS-84**）+ 航向 + 时间戳 + `session_id`（**匿名会话号，不含身份**） |
| 后端处理 | `POST /api/traffic/locate` → 地图匹配 → 路段 + 路段内位置 + `match_confidence` |
| 低置信度 | `match_confidence < 0.6`【待标定】时**不用于重新规划**，提示"定位不稳定，请确认所在道路" |
| 隐私告知文案（**必须原样出现**） | 「**本 App 仅在您进入站前区域后使用您的定位，用于判断您所在的道路并为您匹配路线。定位信息只用于您本人的本次行程，行程结束后即删除；不会记录您的车牌或身份，也不会与路侧摄像头数据关联。您可随时在设置中关闭定位。**」 |
| 拒绝定位 → 降级 | **流程不中断**：降级为「**手动选所在道路 / 只看路况**」，仍可看推荐与路况，**不反复弹窗**（TC-05） |
| 存储 | **只保留本次会话，行程结束即删**；不入库、不给其他司机看 |

## 四、三条硬性要求（**两期都适用**）

1. **三重编码**：**颜色 + 图标 + 文字必须同时出现**，关掉颜色也要能区分四级。缺一视为不通过。
2. **数据不可用显示灰色**，**绝不显示成蓝色**——"没数据"不能被读成"很通畅"。一期判级的可用性门会输出"不可用"，页面必须有这个分支。
3. **不强制、不反复弹窗**；**应急状态下停止路线引导**，替换为"请服从现场指挥"（优先级高于一切推荐）。

> **(2026-10-16 追加)底图补两件事:同源直通 + 瓦片真就绪才算成功。** 起因是实测"底图只出底色层,路和建筑全不见"——旧代码把这种状态判成了 `ok`。查下来是**本机环境**问题,不是功能缺失:
> ① **系统代理黑洞**:本机开着 `http://127.0.0.1:7897`(verge-mihomo),它把境外域名直接黑洞掉;浏览器的请求走它,而 **Node 的 `fetch` 不读系统代理**。实测同一时刻 `curl https://tiles.openfreemap.org/...`(走代理)返回 `000`,`curl --noproxy '*'`(直连)返回 `200`。
> ② **样式命中缓存、瓦片挂死**:样式文件命中 HTTP 缓存 3 ms 返回 200,而 tilejson / `.pbf` 全部挂到超时 —— 单看"样式拉到了"就会误报成功,地图上只剩 Liberty 样式里的底色层。
>
> 修法分两半:
> · **`src/dev/basemap-proxy.ts`(vite 插件,`apply: 'serve'`)**:dev / preview 上挂一条 `/basemap/*` → `https://tiles.openfreemap.org` 的**服务器转发**。走 Node 直连就绕开了系统代理。为了不当开放代理:上游主机写死白名单、**只透传白名单响应头**、**不接受完整 URL**、不落盘、不预取;非 GET/HEAD 返 405;上游超时返 504 带 `code`。`/basemap/health` 返 `{ok:true}` 供前端探测。合规上只做"转发",不缓存不预取(对照 [`../../docs/条款核实.md`](../../docs/条款核实.md) 红线 1 / 必做 2)。
> · **`src/shared/basemap.ts`(地址口径,浏览器与 Node 两侧共用)**:`MapLibreViewer` 建图前先探一次 `/basemap/health`(1.5 s 上限,探不到就当没挂、回落直连上游),探到就把 MapLibre 的 `transformRequest` 里所有上游 URL 换成本地前缀。**生产构建里没有这条路由**,所以靠探测而不是写死或按 `mode` 分支(`vite preview` 看 dist 的场景按 mode 也分不对)。
> · **状态机多一关**:拿到样式后还要 `waitForBasemapTiles()` 轮询 `isSourceLoaded`,**瓦片真的就绪才写 `ok`**;等不到一样算失败,并把已合入的底图**撤回去**(不留"只有底色"的半张底图)。轮询而不是挂 `sourcedata` 监听:黑洞代理下一个事件都不会来。
> · 验收两条不变(① 正常态七件事齐 ② 屏蔽 `tiles.openfreemap.org` 后路网照画),**再加一条**:正常态底图上必须能看见**水系/道路**等非底色图层,不能只是纯色。

11. **detections 读取失败与"未导出/无检出"三分**:感知页把「未导出(服务端无该路)」「读取失败(接口报错)」「无检出(数据为空)」

### 11.1 结论先说:接入前**换不了站**,重构之后才换得了

接入这件事没能"只加一份配置"就完成。原因是接入前的管理端把**站名、路网几何、路段基线、断面编号、
告警剧本、分流建议、感知通道映射**全写死在代码里(`shared/demoNetwork.ts` / `mock/traffic.ts` /
`shared/demoDecision.ts` / `perception/components/channels.ts`)——它只有一份站点的数据,物理上换不了站。
把二站直接喂进去会得到自相矛盾的画面:画二站的路、报一站的名与基线。

> **2026-10-16 现状(IKM4KP)**:站点包**以 Z 为主** —— 包 **B / Y 已删除**,现只剩 **A / Z**,
> **默认包 = Z**(肇庆东站 OSM 真路网)。下面 §11.1 的文件表已按现状更新,§11.2 ~ §11.4 已改写为
> "以 Z 为主"的切站方式、A / Z 对照与包 Z 的口径红线;本节其余文字保留为 2026-10-12 那次的实测记录。

本次因此做了一件**一次性的重构**,把"哪一站"这件事抽成站点包层:

| 文件 | 作用 |
|---|---|
| `src/station-packs/types.ts` | 站点包类型(`StationPack`):站名 + 路网几何 + 断面 + 点位 + 路段基线 + 告警剧本 + 分流建议 + 感知通道 + 同化记录 + 桥接开关 |

### 13.5 监控大屏三栏可拖拽(Issue #81)

主体三栏改成 Element Plus 自带 `ElSplitter` / `ElSplitterPanel`（不加任何新依赖），底部热力带三卡保持原样。

| 项 | 值 |
|---|---|
| 可拖范围 | **仅 `/dashboard` 主体三栏**（左「选择监控」/ 中「全路段状态」/ 右「路段信息」）；底部热力带三卡本单不动 |
| 默认宽度 | 左 **296px**、中弹性、右 **396px**（设计稿按 1440×900 对齐，未改） |
| 最小宽度 | 左 **220px** / 中 **320px** / 右 **280px**（拖到最窄内容不叠压、不溢出，按钮仍点得到） |
| 复位方式 | **双击任意分隔条** → 三栏回到默认 296 / 弹性 / 396 |
| 记忆方式 | 拖完自动写 `localStorage` 键 `hubflow.dashboard.colWidth`（只记左、右两栏，中栏弹性不记）；清缓存或双击即回默认 |
| 换站点包 | 无影响。现在**只有一个包 Z**,顶栏也没有切换器(IKM4XX)—— 拖拽宽度与包无关 |

**已知限制（如实记，不得写成「无障碍已达标」）**：

1. **分隔条只有鼠标 / 触摸拖拽，没有键盘操作**——`ElSplitter` 的 dragger 没有 `tabindex` / `role` / `keydown`（element-plus 2.14.5 源码实测），键盘用户无法调整三栏宽度。宽度本身不影响信息读取（内容都在 DOM 里、可滚动浏览），但**「可调整」这一项对键盘用户不成立**。
2. **双击复位只能用 `mousedown` 自计次实现**，不能挂 `@dblclick`：`ElSplitter` 在 `moveStart` 时会盖一层 `z-index:999` 的 `.el-splitter__mask`（用于吞掉 iframe 的 touch 事件），mouseup 落在遮罩上，mousedown 与 mouseup 的 target 不一致，浏览器不派发 `click`，更没有 `dblclick`。实测事件序列：
   `mousedown:.el-splitter-bar__dragger → mouseup:.el-splitter__mask`。故改为在 `mousedown` 上按 400ms 窗口 + 8px 位移自计次。
3. **记忆宽度不随站点包区分**——将来包多起来时,同一个浏览器切不同包共用同一份左、右栏宽度。

**其余易踩点（改这块前先看）**：

- `.el-splitter-panel` 自带 `overflow: auto`，与既有 `.td-col` / `.td-scroll` 的滚动职责冲突 → panel 一律覆盖成 `overflow: hidden`，滚动仍由内部 `.td-col` 负责（避免双层滚动条或「滚不动」）。
- `.el-splitter-bar` 宽度是 0（只有 16px 的 dragger 绝对定位覆盖在边界上）→ 必须显式给 bar 宽度，本单取 10px，补回原 `.td-body { gap: 10px }` 的栏间距。
- `:size` **必须用 `v-model:size`**，单向绑定不会把拖出来的 px 宽度回写到源变量，`@resize-end` 存进 `localStorage` 的就永远是默认值。
- 中栏**不给 `size`**——`ElSplitter` 会把剩余空间自动瓜分给未指定 `size` 的 panel（中栏不用自己算）。
- 激活态类名是 `.el-splitter-bar__dragger-active`（不是 `.is-active`）。
- 中栏地图是**一块 MapLibre 画布**(容器尺寸变化由 MapLibre 自己跟踪),**改完必须亲手拖一次地图栏**,确认路网仍铺满、取景不跑偏。
- scoped 样式下，`ElSplitter` 子组件内部渲染的元素不带本组件的 scope 属性 → 覆盖规则一律写成 `.el-splitter.td-splitter :deep(...)`，且**后半段不能带 `>` 去直接指向 splitter 的子元素**（dragger 是 `.el-splitter-bar` 的子元素，不是 splitter 的直接子元素）。

**配色（守 §6.2「品牌蓝只表示当前 / 已选 / 可操作」「等级色不得出现在壳层」）**：分隔条竖线默认取 `var(--td-component-border)` 中性灰，hover / 拖拽中取 `var(--td-brand-color)` #0052D9（= 正在被操作）。**刻意不覆盖 element-plus 默认主题蓝之外的状态色**——全仓库不新增任何 `--el-` 变量覆盖，`src/style.css` 的 `--td-*` 仍是唯一色源。

1. `@Observed` 只能在**被装饰的成员变量**上建立订阅。不要写 `private store() { return S.instance(); }` 再 `this.store().xxx` —— 依赖的是临时对象，订阅挂不上，状态变了界面不重绘。正确：父组件 `@State` 持有单例，子组件 `@ObjectLink` 接同一实例（`Tabs` 会缓存已创建页签，`@ObjectLink` 是唯一能穿透缓存的官方机制）。
2. 子组件的入参一律用 **`@Prop`**，不要用普通成员变量（非响应式）。`@Builder` 的值参数只在创建时求值一次，其内部读状态不保证重算 —— 需要随状态变化的块请做成 `@Component` 子组件。
3. **`ForEach` 的缓存键必须带上所有影响渲染的状态**，如 `` `${seg}_${unavailable}_${colorBlind}` ``。键不变时 ArkUI 会复用缓存节点、不重新执行 itemBuilder，导致「开关已切换但颜色不变」或「同一元素图标变灰、文字仍是彩色」这类部分刷新。

**口径红线（本单遵守）**：全部数值来自 fixture（虚拟数据），`is_simulated` 恒为 `true`；不出现「实测 / 实时 / 现场」；**不声称已接入真实定位**（位置来源标注「一期孪生真值」）；字段名与取值集合逐字对照契约 v2.0，`quota` 按契约 §2.1「剩余可预约量」语义承载；**不改契约、不加字段**。

「加载失败、总显示连接不上」的主因不是页面降级没写好，而是**没人告诉使用者该起什么**。本单把这件事补齐：

- **依赖清单**：仓库根新增 `requirements.txt`（实际 import 全集只有 `fastapi` / `starlette` / `uvicorn`，其余标准库）；`README.md`「怎么开始」补「装依赖 → 起接口层 → 起前端」三条命令，并写明 mock / remote 两种模式的区别。
- **健康端点**：`GET /api/traffic/health`（**运维端点、非契约端点**）恒返回 200，逐源给出 `present / fallback / missing` + `used` + 路径，另含 `station` / `version` / `ts` / `missing` / `data_ok` / `resolved` / `is_simulated: true`；与 `traffic.py --check` 共用 `build_health()`，不各写一套。服务活着 ≠ 数据齐，**无数据也 200**；未知 `?station=` 同样 200（`resolved:false`）。
- **环境自检**：`python scripts/env_check.py` 探 `8000 / 8101 / 5173`，HTTP 200 才算过；失败项直接打印该敲的命令；退出码 0 = 全绿、1 = 有缺。支持 `--json`、`--self-test` 与 `--traffic-port/--perception-port/--frontend-port` 覆盖。
- **顶栏运行模式 chip**：`src/api/http.ts` 维护 `backendReachable`（只在 remote 更新，由真实请求成功/失败刷新，**不新造轮询**）；`AppShell.vue` 显示「运行 mock / 运行 remote」，remote 不可达转琥珀警示色，`title` 直接给「起 `traffic.py`」的命令。它与顶栏「数据源（视频链路 / 孪生链路 / 并排）」是两个维度，文案已区分。

## 二十四、切站：为什么不再整页刷新（IKPFR4）

> 本单只动**前端的切站链路**：契约字段、端点路径、响应形状、判级 / 引擎 / 站点包几何（`station-packs/*.network.ts`）**一个字未改**，也没有新增任何业务端点。站点包仍是 `Z`（肇庆东，61 段）/ `GZ`（广州南，708 段）两个。

### 24.1 旧做法为什么只能刷新

切站过去是 `switchPack(key)` + `window.location.reload()`（顶栏切换器与大屏工具条各一份）。原因不是懒：页面里有一批**在 setup 期拍下的快照**，它们读的是模块级变量（`activePack()` / `activePackKey()`），Vue 的响应式系统根本不知道"包键"这个东西存在，改键不会让任何 computed 失效 —— 不整页重来，就只能看着旧数据：

| 位置 | 旧的快照 | 后果 |
|---|---|---|
| `shared/demoNetwork.ts` | 模块单例 `state` + `inited` | 切包后仍返回上一站的几何 |
| `DashboardView.vue` | `const currentPackKey = activePackKey()` | 工具条按钮的选中态不动 |
| `DashboardView.vue` | `const packSegmentIds = new Set(...)` | 路线校验用上一站的段号集合，GZ 的路线整条被判"不在包里" |
| `DashboardView.vue` | `const sourceLabel / geometryNote` | 页脚与图下注脚停在上一站口径 |
| `DashboardView.vue` | `stationName = ref(activePack().station.name)` | 顶栏站名不动 |
| `MapLibreViewer.vue` | `const net = DEMO_NETWORK.segments` | 地图画的是上一站的路网 |
| `MapLibreViewer.vue` | `pins = cameraPins()` / `sourceLabel` | 图钉与水源地标签停在上一站 |

### 24.2 版本号 + 订阅：让"模块级键"变成可观察的

`src/station-packs/index.ts` 新增三样东西（**该文件保持零依赖**，因为它同时被 `vite.config.ts` 的 Node 侧 mock 引用，所以这里没有也不许有 `import { ref } from 'vue'`）：

```ts
let version = 0
const listeners = new Set<() => void>()
export function packVersion(): number
export function onPackChange(fn: () => void): () => void   // 返回取消订阅
```

- `switchPack(key)` 只在**键真的变了**之后 `version++` 并通知订阅者；同一个键重复点不重跑流程。
- `setActivePackKey()`（入口注入 / mock 每请求现取站）**故意不发通知**：前者发生在挂载前、后者在 Node 进程里，都不是"用户切站"。
- 订阅回调是**同步**跑的，所以只让它改响应式 ref（各组件自建 `packTick`），真正的重绘交给 Vue 的 watch —— 那时几何已经按新包重建完了。

所有 setup 期快照随之改造：`demoNetwork.ts` 增加 `resetNetwork()`，且 `ensureInit()` 现在**按包键自校验**（`initedKey !== activePackKey()` 就重建）；`currentPackKey` 改 `ref`；`packSegmentIds` / `packSegmentCount` / `siteMeta` / `packSegments` / `sourceLabel` / `geometryNote` / `packNote()` / `stationName` 兜底 / `directionsAvailable` 改 computed；`MapLibreViewer` 的 `net` 改 `shallowRef`，`pins`、`sourceLabel` 改 computed。

### 24.3 切站唯一入口：`shared/stationSwitch.ts`

顶栏「线路图切换器」与大屏工具条**共用** `switchStation(key)`，顺序固定：

1. `switchPack(key)` —— 换键、`version++`、广播；
2. `resetNetwork()` —— 路网几何按新包重建；
3. **站内状态一律重置** + 中止在途请求（业主 2026-10-21 裁定，见 24.5）；
4. **缓存优先**：同步吃内存缓存渲染首屏（有缓存就不显示加载态）；
5. 后台立刻补拉一次（不等 SSE 的下一个 2 s tick）；
6. 同步 URL `?pack=`。

地图这边**只换数据**：`source.setData(...)` + 重贴 filter + 重建图钉/落客点/方向层 + `fitToNetwork` 重新取景；**不重建 `Map` 实例、不 `setStyle`** —— 底图瓦片是跨站可复用的公共资源，重建一次就是几 MB 重下加一次白屏。

`src/` 下 `grep -rn "location.reload"` 现在**只剩两句注释**（说明历史做法），代码里 0 命中。

### 24.4 缓存优先：键、预热时机、失效规则

新增 `src/shared/stationCache.ts`：内存 `Map<string, StationSnapshotCache>`，**只存两站**，结构 `{ key, overview, segments, meta, thresholds, alerts, factors, matrix, ts }`（字段取自 `shared/traffic.ts` 的类型）。

- **缓存键 = 站点包键**（`Z` / `GZ`）。写和读都按这个键分桶；替别站预热时用 `SnapshotFetchOptions.station` 把请求钉在目标站上（仍是同一个 `X-Station-Pack` 头，只是取值来源换成显式参数）—— 绝不允许"拿本站响应写别站桶"。
- **预热时机**：首屏 `refresh()` 成功之后，`requestIdleCallback`（无此 API 的浏览器用 `setTimeout` 1 s 兜底）把两站各拉一次 `overview / segments / meta / thresholds / alerts / factors`。预热**失败静默**：不弹错、不进 `failedPanels`，切过去自然走骨架屏 + 正常刷新。
- **失效规则只有两条**：① 页面进程结束即全部失效（内存 Map 的自然属性，**不写 localStorage** —— 缓存快照会过期，落盘就成了"昨天的路况"且无人察觉）；② 条目超过 `CACHE_TTL_MS`（10 min）视为过期，`readStationCache()` 直接返回 `null`。除此之外切站即刷新、新数据按字段替换，不做"手动清缓存"。
- **两档体验**：热缓存 = 同步吃缓存，首屏立刻可见（目标 ≤0.3 s，不出现加载态）；冷缓存（首次访问该站 / 预热未完成）= 一条**极简骨架条**「正在加载「GZ」的首屏快照…」，页面主体不白屏，目标 ≤1.5 s 出数据。
- **不许冒充最新**：用缓存渲染期间，页面上有「缓存 · 刷新中 —— 当前显示「GZ」的缓存快照（缓存于 N s 前）…」提示条，页脚同时标「数据标识:内存缓存快照 · 后台刷新中」；后台刷新一回来两处同时撤掉。

### 24.5 业主裁定：切站时站内状态一律重置

`selectedId`、`hoverChip`（地图浮牌与图钉浮牌）、路线 session（`recommended` / `routeOptions` / 手动起点 / 定位结果）、热力带选中（监控范围筛选）、深链选中（`?segment=` 重新生效一次）、页面滚动位置（整页 + 左右两栏的内部滚动容器）—— **全部清空、回到顶部，不做跨站恢复**。理由：段号、session、点位都是各站自己的命名空间，跨站"恢复"只会把 A 站的段号塞进 B 站。

清空之后：有缓存就用缓存把首屏铺满；没有缓存就骨架条 + 等这一轮刷新。防御上还有一道闸：`refresh()` 记下发请求时的站键，响应回来后若 `activePackKey()` 已变，整批响应**直接丢弃**，同时切站时会 `AbortController.abort()` 掉在途请求 —— 两道都留，中止省带宽、校验兜底。

### 24.6 `?pack=` 深链与 SSE

- 入口（`main.ts`）读一次 URL 的 `pack`（hash 路由下取 `#/…?pack=GZ` 的查询段，也兼容真实 search 段）：命中 `PACKS` 就 `switchPack()`（同时写 `localStorage['hubflow.stationPack']`）；**坏键不报错、不写盘**，落回 `restorePackKey()` 的既有守卫语义（未知键 → 注入值 / 默认包）。
- 切站后用 `history.replaceState` 把 `?pack=` 写回地址栏（不触发路由跳转 —— 跳转会重建页面组件，等于把省下来的刷新又加回去）。
- **SSE 不随站切换重连**：`subscribeTrafficSnapshot()` 本来就是不带站的裸通道，切站不重建连接；但切站后**立刻补拉一次**（`switchStation` 的第 ⑤ 步），不用等下一个 2 s tick。

### 24.7 非大屏页面怎么办

决策层 / 感知层没接缓存链路，只靠 `App.vue` 的 `<router-view :key="stationRemountKey">` 兜底：切站时换 key → 页面组件重新 setup、按新包重取数据，**不重新请求文档、不重下底图**。监控大屏自己注册了原地切站钩子，**不会**走这条重挂载。

> **2026-10-23 口径改版（业主）**：「缩放不用这么夸张，不用上升到全国的，缩放到能看见两个站点就可以了，缩放和移动是同步进行的，一边缩放一边移动」。据此把原来的「缩远 → **停在 5.5 平移** → 放大」三段并成两段，且每段都是 `center` 与 `zoom` 一起插值（见 §25.3）。

### 25.3 镜头状态机与「只有一个动画在跑」

```text
national --(选站)--> entering --(放大 + 平移同帧进行 + 路网淡入)--> station
station  --(点另一站)--> leaving --(缩远到「两站同框」+ 平移同帧进行)--> entering --(落进目标站)--> station
```

两段都是**缩放与平移同时进行**：`easeTo({center, zoom})` 与 `fitBounds()` 本身就同时插值 center/zoom，没有任何一段是「固定缩放下只平移」。
**缩远多少不再写死**：`transitCamera()` 用「当前相机中心 + 目标站站区框」的合并包围盒现算（`cameraForBounds` + 对称留白），得到的就是「两站刚好同框」那一档 —— 实测 Z↔GZ 约 **9.9 档**（旧版固定 5.5，等于先飞一趟省域/半个中国再飞回来）；从全国进站则**根本不缩**（起点 3.3 已更远），直接一趟放大。

`flyToStation()` 用 `easeTo` + `fitBounds` 链，**不用 `setInterval` 逐帧改 center**（Vue 不参与逐帧渲染）。模块级 `runSeq` 保证单通道：每次发起 `++runSeq; map.stop()`，每一步 `await waitMoveEnd()` 后校验代次，代次变了立刻返回 `cancelled` 且后续步骤一步都不跑 —— 于是 T1/T2/T3 任意时刻点另一站，都是从**当前相机**重开，最终状态必然等于**最后点的那个站**（连点不叠加、不排队）。

`prefers-reduced-motion: reduce` 时取消缩远 / 平移，只做一次 200 ms 的 `fitBounds` 直接到站区，站名 / 路网 / 信息照旧。

### 25.4 图层规则（「其他站的路线不展示」落到开关上）

唯一开关在 `MapLibreViewer.vue` 的 `applyModeLayers()`，按 `motionPhase` 分派：

| 图层族 | 全国 | 过渡中 | 站区 |
|---|---|---|---|
| 路网 / 热力 / 选中 / 路线（`hubflow-route-*`） | 隐藏 | 隐藏 | 显示 |
| 方向标记 | 隐藏 | 隐藏 | 按顶栏「设置」开关 |
| 站点 pin（命中层 / 实心点 / 站名） | 显示 | 显示 | 隐藏 |
| 兜底轮廓（中国示意） | 底图不可用时显示 | 同左 | 隐藏 |

### 25.5 切站时序（信息不串站）

1. **选站**（pin / 全国浮层卡片 / 工具条按钮 / 顶栏切换器，全部走 `pickStation()` → `switchStation()`）：站内状态一律重置、在途请求中止、`arriving = true`（数据先挂住不上屏）。
2. **镜头**：`national → entering → station`（进站）/ `station → leaving → entering → station`（切站）；左右栏在全国模式收起（250 ms 宽度过渡）。取景前 `resizeMap()` 会**等容器宽高连续两帧不变**（上限 500 ms）再 `resize()` + `fitBounds` —— 只等一帧不够：切口令后 `fitBounds` 会落在宽度过渡中途（实测读到 1194 px、最终 1886 px），落点会偏（`← 全国` 实测偏东约 24°，中国被挤到画面左侧）。
3. **到站**（地图 `emit('arrived')`）；`refresh()` 拿到的响应 `await whenArrived()` 之后才提交面板；缓存快照同样先挂在 `pending`，到站后一次铺上。**4 s 兜底**：动画异常时不至于让数据永远不落地。
4. **路线**：`route/recommend` 返回后淡入。失败 → 镜头仍到站区，面板如实「本次未取到 + 重试」，**不回退成上一站数据**。

## 二十六、缩放时路网不再糊成一片：线宽 / 热力 / 图钉 / 图例四件事（业主 2026-10-19~20 交办）

> 本单只动**显示层**：判级、契约字段、`stations/*.json`、引擎产物一律没动。
> 四条口径全部来自业主当面反馈，逐条对应下文。

### 26.1 问题原话与根因

业主第一次反馈：「**一缩小就全都缩一块了，就好像外面包裹的那一层颜色有点看着难受，但是这个颜色又不能完全去掉**」。
第二次追加：「还是和一坨一样，就是每个道路都要颜色，然后周围还有往外衍生的一圈淡淡的颜色，把那个去掉怎么样」。

根因不是颜色，是**宽度单位**：`line-width` / `line-opacity` 的取值单位是**屏幕像素**，缩放时**不跟着变**；
而路网在屏幕上的**跨度**按 `2^-d` 缩、**面积**按 `4^-d` 缩。线宽不收，同样的线在更小的地盘上重叠，
覆盖率就按 `2^d` 爆（缩 2 档 ×4、3 档 ×8），于是糊成一团、外面像包了层同色雾。
三层里最猛的是 `LAYER_HEAT` 基准 26/22 px（彩色主线 5.5/4.5 的 4.7 倍）且半透明。

第二层原因是**摄像头图钉**：`new Marker({ element })` 造的是 DOM 元素，屏幕像素恒定、天然不随 zoom 缩。
缩远后路网只剩几十像素，20 px 的图钉却还是 20 px。
（影响面如实记：图钉只画**带坐标的通道** —— **Z 站 6 路、GZ 站 0 路**（`stationGZ.ts` 的 `channels: []`）。
所以这一项在 Z 站生效、**在 GZ 站没有可见效果**；业主抱怨糊成一团的 GZ 708 段，主因是热力晕染（§26.3）
与方向箭头，不是图钉。别把图钉当主因。）

### 26.2 四项改动

| # | 事项 | 做法 |
|---|---|---|
| ① | 线宽随缩放收缩 | 新增 `lineScaleOf()`：`fitZoom` 及更近恒为 1（默认视野观感不动），比默认档缩远则 `2^-d`，下限 0.15。`applyLineScale()` 逐帧贴回三层 `line-width` |
| ② | 热力额外淡出 | `heatFadeOf()`：`2^(-0.8d)`，下限 0.25 —— **不归零**，业主明确「颜色不能完全去掉」 |
| ③ | 图钉随缩放收缩/淡出 | 两层 DOM：外层 `.cam-pin-wrap` 交给 Marker 定位（不能碰它的 `transform`），内层 `.cam-pin` 承接 `scale()`。`camPinScaleOf()` 下限 0.28；`camPinOpacityOf()` 缩远 1 档开始淡、1.6 档淡尽并放开 `pointer-events` |
| ④ | 桌面端图例可收起 | 原先只有 ≤1180 窄屏有收起键（桌面 `.legend-toggle { display:none }`），图例压住左下角路网没法收。改为桌面也出收起键，状态共用全局 `legendVisible` 并落 `localStorage` |

### 26.3 四级视图不再画热力晕染

`LAYER_HEAT` 的注释从第一版起就写着「只指数视图有值；四级视图 heat 恒 0，等于不画」，
但实现里只有「流量版返 0」「摄像头未覆盖返 0」两条守卫，**漏了 `isIndex` 判断** ——
四级视图下**有摄像头覆盖的段**照样给 `0.1–0.6`，26 px 同色半透明宽带在路口叠成一片明显的橙绿晕。
`heatOf()` 开头补 `if (!isIndex.value) return 0`。属**代码与注释不一致**，这里补齐，不是口径变更。

**影响面如实记（2026-10-23 实测，别把这项当成"糊成一坨"的主因）**：
heat 只在**摄像头覆盖段**上非零 —— GZ 708 段里 **6 段**（6 路摄像头）、Z 61 段里 **6 段**（`querySourceFeatures`
实测四级视图 6 条非零、指数视图同样 6 条）。所以本项修的是**局部路口那一圈雾**；
广州南站默认视野里压住路网的是 **752 个方向箭头 symbol**，属业主 2026-10-22 明确推迟的一项（见 §26.6）。

### 26.4 `fitZoom` 为什么不能写死

取景函数 `fitStationInstant()` / `fitOverviewInstant()` 在 `fitBounds()` **之后**才写 `fitZoom = map.getZoom()`
—— Z 站演示范围 500 m、GZ 站 1000 m，两站默认档本来就不同，写死 zoom 14 会一站准一站错。

**⚠️ 而且它必须在「动画切站」那条路上也写回（独立审查 P0，已修）**：
「全国 → 点站」（快链 `?station=` 同样走）用的是 `flyToStation()` 的**动画版取景**，
**不经过**上面两个 instant 函数；只在 instant 版写 `fitZoom`，主路径上 `fitZoom` 会一直停在首屏全国档（≈3），
于是 `d = fitZoom - zoom` 恒为负 → `lineScaleOf / heatFadeOf / camPinScaleOf` **全部恒等 1**，
业主的问题在最常用的一条路上一点没改（而「改窗口大小」会走 `syncCamera(false)` 偶然自愈，正好掩盖这个 bug）。
现在收成一个 `commitFitZoom(map)`：写 `fitZoom` + 重贴线宽/热力/图钉，在
`fitStationInstant` / `fitOverviewInstant` / `await flyToStation()` / `await flyToOverview()` 四处都调。

## 二十七、方向箭头重做：150 m 与道路同宽、远档等比缩小 + 淡出 + 200 m 以远不画（业主 2026-10-23 定版）

### 27.1 新口径（三段式）

| 比例尺档 | zoom | 行为 |
|---|---|---|
| ≥150 m 档 | ≥15.5 | **基准 7.5 px**（`DIR_ICON_PX / 64`），透明度 1；**放大不再变大** |
| 150→200 m | 15.0~15.5 | **等比缩小**（`2^-d`）+ **线性淡出**（1→0） |
| ≤200 m 档 | ≤15.0 | **透明度 0，一支不画** |

### 27.2 改了什么（单文件 `MapLibreViewer.vue`）

- 常量：`DIR_ICON_PX=7.5` / `DIR_ICON_CANVAS=64` / `DIR_ZOOM_FULL=15.5` / `DIR_ZOOM_FADE=15.0`。
- `dirIconSizeOf(zoom)`：`d<=0` 恒基准；远档 `基准 × 2^-d`，下限 0.03。
- `dirIconOpacityOf(zoom)`：线性淡出；与图钉淡出同风格但**独立参数**（图钉淡出下限不归零、箭头归零——两者口径不同，业主分别定的）。

- `directionLayerSpec()` 只放基准值：MapLibre 硬性限制 `zoom` 只能进顶层 interpolate 输入位，写错整个 setStyle 抛错（main 早期踩过，git 有案）；真实值一律运行时刻贴回。
- 图例文案补口径说明一行。

### 27.3 顺手修：motionPhase 卡死（main 既有 bug，与本单同文件同函数）

症状：深链 `?station=GZ` 直进 / 镜头飞行被中断后，路网与箭头一支不画，缩放也不恢复。

## 三十二、效果对比补「处置前后三项」：演示值换成引擎同一窗口现算（TC-09，2026-10-26）

第二十八章把「效果对比」从空壳接上了引擎三组真产物，但手册第 17 章要的报表是
**三组对照 + 处置前后三项**（排队长度峰值 / 拥堵持续时间 / 饱和度和差）。三项当时没有引擎产物，
页面用的是 `shared/demoDecision.ts` 的 `ACK_COMPARISON` **写死的演示值**（340→180 m / 26→11 min /
3.42→2.05），属于「拿演示值冒充报表」。本章把它换成引擎现算的真值。

### 32.1 口径（引擎侧 `work/engine/run.py` 的 `_compare_treatment()`）

- **等长时间窗**：处置前 = 组①（不推荐）、处置后 = 组③（协同推荐），两组跑**同一个**评估窗口
  （同一 `base_ts` / 同一 `window_sec` / 同一车辆群 / 同一站点包参数），差异只来自推荐机制。
  **不虚构两个时间段**——本项目没有「处置前 30 min」的真实历史窗口，编一个就是造假。
- **对比范围 = 两侧橙红段并集**（`scope`）：处置前橙红段 ∪ 处置后橙红段。若只算「处置后自己的橙红段」，
  协同推荐把流量挪走的段会凭空消失，分母变小造成假优势；并集保证两侧同一段号集合、分母可比。
- **三项口径**（原文写进 `metrics.*.formula`，下游照抄不改写）：
  - 排队长度峰值：逐时段 `q_veh = max(0, x-1) × capacity_per_slot`；
    `L_q = min(L_seg_m, q_veh / 车道数 × queue_headway_m)`，取 scope 内最大。
  - 拥堵持续时间：逐时段判 **`x >= 1.0`**（过饱和的物理定义，**不是等级档位**）——按等级橙档 `x>=0.8`
    去判，三组整窗都算「拥堵 15 min」，一点区分度都没有；按过饱和判才有可比差异。取最长**连续**
    过饱和时段数 × `slot_minutes`。
  - 饱和度和：scope 内各段窗口内**最大**饱和度之和。
  - `queue_headway_m` 读 `stations/thresholds.json` 的 `grading`（与孪生侧 `METRIC_FORMULAS` 同一出处），
    非正数直接 `SystemExit`，**代码里不写死**。

### 32.2 没有对比对象时如实标不可用

`treatment.available = false` + `unavailable_reason`，三项的 `before/after/delta` **一律 `null`**。
最常见的情形：用只有 1 个时段的上游快照跑（`--segments work/twin/out/latest/segments_twin.json`
的 `window_sec=60` → 1 个 slot），窗口内没有任何段进橙红档，scope 为空。
此时**绝不能输出 0 → 0**——那读起来像「改善到完美」。接口层 `_report_treatment()` 还兜了一层，
老产物就算带了 0 → 0 也会被改判成 null。

## 三十三、备选路线补上 + 路线配色统一蓝色系（业主 2026-10-28）

### 33.1 业主原话与拆解

> 「先帮我把备用线路搞定，然后如果要显示路线或者备用路线的话，都要用蓝色道路来显示规划路线和备用路线，
> 选中的路线为天蓝色，备用路线如果被选中就变成选择的路线，备用路线用暗蓝色」

拆成三件事：① 页面上要**真的有备选**（以前常年 0 条）；② 画在地图上的路线全部走**蓝色系**；
③ 选中的那条（不管是推荐还是备选）**亮成天蓝**。

### 33.2 备选 0 条的修复在引擎侧，不在前端

前端一直照实渲染——问题出在引擎那边 OD 根本没算出来备选（详见
[`work/engine/README.md`](../engine/README.md) §5.3）：真网只有 44 节点 / 94 条有向边，
Yen 搜索深度 K=3 时前几条最短路互相重叠 0.77~0.94，被站点包 `max_path_overlap = 0.7` 全部筛掉。
本轮把**搜索深度**提到 `CANDIDATE_SEARCH_K = 30`（属手册允许的"做法"，重叠度门槛与站点包一个字节没改），
真网 4 条 OD 里 **2 条有备选**（OD-R-001 / OD-R-004，绕行 +80~125 m 的真不同走廊），
另外 2 条拓扑上唯一通路，按契约如实 `no_alternative`。

前端这侧只补了「能被选中」和「配色」两件事。

### 33.3 三档蓝（`MapLibreViewer.vue`）

| 语义 | 颜色 | 线型 |
|---|---|---|
| 规划路线（推荐，未选中） | 品牌蓝 `#0052D9` | 3.4 px 实线 + 品牌蓝光晕 |
| 未选中的备用路线 | 暗蓝 `#1E3A8A` | 3 px 虚线（备选 1 长虚 12/6、备选 2 短虚 2.5/4.5，各带 ±2 px 平行偏置） |
| **被选中的那条**（推荐或备选都算） | 天蓝 `#38BDF8` | 4.2 px 实线 + 天蓝光晕，压在最上层 |

- 两条备选**同色**（业主只要蓝色系），靠**虚线节律 + 平行偏置**区分，不再靠色相。
- 「选中」不是新增的第五种颜色，而是**覆盖**掉该路线原本那档蓝。实现上：
  新增 `LAYER_ROUTE_PICK` / `LAYER_ROUTE_PICK_HALO` 两个天蓝图层画在最上面，
  同时底层 `LAYER_ROUTE` / `LAYER_ROUTE_ALT1` / `LAYER_ROUTE_ALT2` / `LAYER_ROUTE_DEP` 的 filter 都套
  `routeFilterExcludingPicked(...)` 把**被选中那条的段号剔除**——否则天蓝细线会被自己的暗蓝粗线盖住
  （MapLibre 不做 alpha 混合替换）。
- 离站路线仍用紫 `#7B61FF`：它不在「规划 / 备用 / 选中」这条行程层级里，是另一段行程。
- 与四级判级色（`#2BA471` / `#E9B32E` / `#E37318` / `#D54941`）、数据不可用灰 `#8B8B8B` 均不撞。
