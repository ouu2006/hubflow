### 3.1 一期：**绑定演示车**

| 项 | 口径 |
|---|---|
| 数据来源 | `GET /api/traffic/vehicles`（读 `vehicles.json`，**孪生内部数据**） |
| 绑定规则 | App 一期**只绑一辆"演示车"**——`is_demo_bound: true` 的那一辆，**同一时刻最多一辆** |
| 为什么要绑 | 一期车辆就在孪生里，**没有真实定位可上报**；绑一辆车让 App 能显示"它的位置、推荐路线、备选、离站路线"，证明**双端同源**（M1-5） |
| 位置从哪来 | **后端直接给**（孪生真值），App **不做任何定位请求** |
| 口径纪律 | 一期 App **不得**声称"已接入真实定位"；`GET /api/traffic/vehicles` **二期下线** |

### 3.2 二期：真实定位上报（**一期只留接口位，不实现**）

| 项 | 口径 |
|---|---|
| 上报频率 | 进入站前围栏后 **每 5–10 秒上报一次** |
| 权限 | **用户主动同意**才开启定位；**首次进入围栏时请求**，不在启动时弹 |
| 上报内容 | 位置（统一转 **WGS-84**）+ 航向 + 时间戳 + `session_id`（**匿名会话号，不含身份**） |
| 后端处理 | `POST /api/traffic/locate` → 地图匹配 → 路段 + 路段内位置 + `match_confidence` |
| 低置信度 | `match_confidence < 0.6`【待标定】时**不用于重新规划**，提示"定位不稳定，请确认所在道路" |
| 隐私告知文案（**必须原样出现**） | 「**本 App 仅在您进入站前区域后使用您的定位，用于判断您所在的道路并为您匹配路线。定位信息只用于您本人的本次行程，行程结束后即删除；不会记录您的车牌或身份，也不会与路侧摄像头数据关联。您可随时在设置中关闭定位。**」 |
| 拒绝定位 → 降级 | **流程不中断**：降级为「**手动选所在道路 / 只看路况**」，仍可看推荐与路况，**不反复弹窗**（TC-05） |
| 存储 | **只保留本次会话，行程结束即删**；不入库、不给其他司机看 |

## 四、三条硬性要求（**两期都适用**）

1. **三重编码**：**颜色 + 图标 + 文字必须同时出现**，关掉颜色也要能区分四级。缺一视为不通过。
2. **数据不可用显示灰色**，**绝不显示成蓝色**——"没数据"不能被读成"很通畅"。一期判级的可用性门会输出"不可用"，页面必须有这个分支。
3. **不强制、不反复弹窗**；**应急状态下停止路线引导**，替换为"请服从现场指挥"（优先级高于一切推荐）。

> **(2026-10-16 追加)底图补两件事:同源直通 + 瓦片真就绪才算成功。** 起因是实测"底图只出底色层,路和建筑全不见"——旧代码把这种状态判成了 `ok`。查下来是**本机环境**问题,不是功能缺失:
> ① **系统代理黑洞**:本机开着 `http://127.0.0.1:7897`(verge-mihomo),它把境外域名直接黑洞掉;浏览器的请求走它,而 **Node 的 `fetch` 不读系统代理**。实测同一时刻 `curl https://tiles.openfreemap.org/...`(走代理)返回 `000`,`curl --noproxy '*'`(直连)返回 `200`。
> ② **样式命中缓存、瓦片挂死**:样式文件命中 HTTP 缓存 3 ms 返回 200,而 tilejson / `.pbf` 全部挂到超时 —— 单看"样式拉到了"就会误报成功,地图上只剩 Liberty 样式里的底色层。
>
> 修法分两半:
> · **`src/dev/basemap-proxy.ts`(vite 插件,`apply: 'serve'`)**:dev / preview 上挂一条 `/basemap/*` → `https://tiles.openfreemap.org` 的**服务器转发**。走 Node 直连就绕开了系统代理。为了不当开放代理:上游主机写死白名单、**只透传白名单响应头**、**不接受完整 URL**、不落盘、不预取;非 GET/HEAD 返 405;上游超时返 504 带 `code`。`/basemap/health` 返 `{ok:true}` 供前端探测。合规上只做"转发",不缓存不预取(对照 [`../../docs/条款核实.md`](../../docs/条款核实.md) 红线 1 / 必做 2)。
> · **`src/shared/basemap.ts`(地址口径,浏览器与 Node 两侧共用)**:`MapLibreViewer` 建图前先探一次 `/basemap/health`(1.5 s 上限,探不到就当没挂、回落直连上游),探到就把 MapLibre 的 `transformRequest` 里所有上游 URL 换成本地前缀。**生产构建里没有这条路由**,所以靠探测而不是写死或按 `mode` 分支(`vite preview` 看 dist 的场景按 mode 也分不对)。
> · **状态机多一关**:拿到样式后还要 `waitForBasemapTiles()` 轮询 `isSourceLoaded`,**瓦片真的就绪才写 `ok`**;等不到一样算失败,并把已合入的底图**撤回去**(不留"只有底色"的半张底图)。轮询而不是挂 `sourcedata` 监听:黑洞代理下一个事件都不会来。
> · 验收两条不变(① 正常态七件事齐 ② 屏蔽 `tiles.openfreemap.org` 后路网照画),**再加一条**:正常态底图上必须能看见**水系/道路**等非底色图层,不能只是纯色。

### 11.1 结论先说:接入前**换不了站**,重构之后才换得了

3. **默认态不碰站点包基线**——站点包声明的那套天气是**观测**（包 A 声明大雨，其 SEG-003 / SEG-007 基线里本就烘了 F01 大雨 ×0.75）。`applyFactors` 只在**注入过**（`scenarioState` 非空）时才剔除包里烘入的环境因素再重放；未注入时**逐位不动**，避免把整张基线推高一档（实测踩过：x 0.54→0.71、level 2→3，QA 基线全漂）。
4. **注入前后对照取未抖动口径**——抖动每轮随机，拿抖动后的快照当对照会把噪声算成"注入效果"；对照由 mock 侧 `levelsAfterFactors()` 算，前端不算。

### 13.5 监控大屏三栏可拖拽(Issue #81)

主体三栏改成 Element Plus 自带 `ElSplitter` / `ElSplitterPanel`（不加任何新依赖），底部热力带三卡保持原样。

| 项 | 值 |
|---|---|
| 可拖范围 | **仅 `/dashboard` 主体三栏**（左「选择监控」/ 中「全路段状态」/ 右「路段信息」）；底部热力带三卡本单不动 |
| 默认宽度 | 左 **296px**、中弹性、右 **396px**（设计稿按 1440×900 对齐，未改） |
| 最小宽度 | 左 **220px** / 中 **320px** / 右 **280px**（拖到最窄内容不叠压、不溢出，按钮仍点得到） |
| 复位方式 | **双击任意分隔条** → 三栏回到默认 296 / 弹性 / 396 |
| 记忆方式 | 拖完自动写 `localStorage` 键 `hubflow.dashboard.colWidth`（只记左、右两栏，中栏弹性不记）；清缓存或双击即回默认 |
| 换站点包 | 无影响。现在**只有一个包 Z**,顶栏也没有切换器(IKM4XX)—— 拖拽宽度与包无关 |

**已知限制（如实记，不得写成「无障碍已达标」）**：

1. **分隔条只有鼠标 / 触摸拖拽，没有键盘操作**——`ElSplitter` 的 dragger 没有 `tabindex` / `role` / `keydown`（element-plus 2.14.5 源码实测），键盘用户无法调整三栏宽度。宽度本身不影响信息读取（内容都在 DOM 里、可滚动浏览），但**「可调整」这一项对键盘用户不成立**。
2. **双击复位只能用 `mousedown` 自计次实现**，不能挂 `@dblclick`：`ElSplitter` 在 `moveStart` 时会盖一层 `z-index:999` 的 `.el-splitter__mask`（用于吞掉 iframe 的 touch 事件），mouseup 落在遮罩上，mousedown 与 mouseup 的 target 不一致，浏览器不派发 `click`，更没有 `dblclick`。实测事件序列：
   `mousedown:.el-splitter-bar__dragger → mouseup:.el-splitter__mask`。故改为在 `mousedown` 上按 400ms 窗口 + 8px 位移自计次。
3. **记忆宽度不随站点包区分**——将来包多起来时,同一个浏览器切不同包共用同一份左、右栏宽度。

**其余易踩点（改这块前先看）**：

- `.el-splitter-panel` 自带 `overflow: auto`，与既有 `.td-col` / `.td-scroll` 的滚动职责冲突 → panel 一律覆盖成 `overflow: hidden`，滚动仍由内部 `.td-col` 负责（避免双层滚动条或「滚不动」）。
- `.el-splitter-bar` 宽度是 0（只有 16px 的 dragger 绝对定位覆盖在边界上）→ 必须显式给 bar 宽度，本单取 10px，补回原 `.td-body { gap: 10px }` 的栏间距。
- `:size` **必须用 `v-model:size`**，单向绑定不会把拖出来的 px 宽度回写到源变量，`@resize-end` 存进 `localStorage` 的就永远是默认值。
- 中栏**不给 `size`**——`ElSplitter` 会把剩余空间自动瓜分给未指定 `size` 的 panel（中栏不用自己算）。
- 激活态类名是 `.el-splitter-bar__dragger-active`（不是 `.is-active`）。
- 中栏地图是**一块 MapLibre 画布**(容器尺寸变化由 MapLibre 自己跟踪),**改完必须亲手拖一次地图栏**,确认路网仍铺满、取景不跑偏。
- scoped 样式下，`ElSplitter` 子组件内部渲染的元素不带本组件的 scope 属性 → 覆盖规则一律写成 `.el-splitter.td-splitter :deep(...)`，且**后半段不能带 `>` 去直接指向 splitter 的子元素**（dragger 是 `.el-splitter-bar` 的子元素，不是 splitter 的直接子元素）。

**配色（守 §6.2「品牌蓝只表示当前 / 已选 / 可操作」「等级色不得出现在壳层」）**：分隔条竖线默认取 `var(--td-component-border)` 中性灰，hover / 拖拽中取 `var(--td-brand-color)` #0052D9（= 正在被操作）。**刻意不覆盖 element-plus 默认主题蓝之外的状态色**——全仓库不新增任何 `--el-` 变量覆盖，`src/style.css` 的 `--td-*` 仍是唯一色源。

### 13.6 告警判级取当前路段快照（Issue #75 第④条 / 回归修复 IKLLXG）

**一句话口径**：告警自带的 `level` 是**派生时的记录值**（站点包预置剧本），与**当前路段快照**可能不同步——页面上**一律按快照判级**显示，快照缺该路段时**退回告警记录值**，不编造。

**四处（原话是"四处"，现在收成一份实现）**：决策队列 / 决策工作台 / 大屏底部告警条 / 大屏右栏关联告警。

| 项 | 落点 |
|---|---|
| **唯一实现** | `src/shared/traffic.ts` 的 `alertLevelOf(a, findSegment)` |
| 大屏右栏关联告警 | `AlertList.vue` 的 `levelOf` 是**必需 prop**（`DashboardView.vue` 传 `segLevelOf`）——**漏传会被 `vue-tsc` 拦下**，这正是本单要防的"下次迁移再丢一次" |
| 大屏底部告警条 | 同页 `segLevelOf()`（同一函数） |
| 决策队列 / 决策工作台 | `DecisionView.vue` 的 `segLevel()`（同一函数，`findSegment` 换成 `segMap` 查表） |

**ArkTS 状态管理约定（改这块前必读，已踩坑 5 轮）**：

1. `@Observed` 只能在**被装饰的成员变量**上建立订阅。不要写 `private store() { return S.instance(); }` 再 `this.store().xxx` —— 依赖的是临时对象，订阅挂不上，状态变了界面不重绘。正确：父组件 `@State` 持有单例，子组件 `@ObjectLink` 接同一实例（`Tabs` 会缓存已创建页签，`@ObjectLink` 是唯一能穿透缓存的官方机制）。
2. 子组件的入参一律用 **`@Prop`**，不要用普通成员变量（非响应式）。`@Builder` 的值参数只在创建时求值一次，其内部读状态不保证重算 —— 需要随状态变化的块请做成 `@Component` 子组件。
3. **`ForEach` 的缓存键必须带上所有影响渲染的状态**，如 `` `${seg}_${unavailable}_${colorBlind}` ``。键不变时 ArkUI 会复用缓存节点、不重新执行 itemBuilder，导致「开关已切换但颜色不变」或「同一元素图标变灰、文字仍是彩色」这类部分刷新。
