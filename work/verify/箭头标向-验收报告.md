## 2. 三个证据源如何**各自独立**验证，再交叉

三套证据互不依赖实现细节，且刻意用**不同的口径**算同一件事，交叉点就是"三者一致"：

| 证据源 | 口径（它自己怎么算出"应该朝哪"） | 依赖什么 | 能证什么 / 不能证什么 |
|---|---|---|---|
| **L1 后端自检**（`work/engine/tools/audit_segment_direction.py`） | 直接读后端 `steps[]`：断言几何首末点 == 声明 from/to（<0.5 m）、`coords_offset↔travel_offset` 互逆（<1e-6）、reverse 段 `offset_m=0` 的 `start_point` == `coords[0]`（<1.0 m）且 `steps[0].direction=='reverse'`、steps 链首尾相接（<0.5 m）、`Σsteps.length − trim ≈ routes.length`（<0.2 m）、reverse 段中点往返（<1.5 m） | 后端自己的 `steps` 输出与网拓扑 | 证"后端吐出来的行进序与拓扑自洽"；**不证**前端画成什么样 |
| **L2 数值快照**（`work/verify/direction_snapshot.json`） | **绕过前端、也绕过接口**，直接读仓库真网产物 `work/twin/netpack/network_junction.json` 的 `edges[]`，用独立的平面近似重算每段 `length_m` / `bearing_coords_order` / `bearing_travel` / 中点 | 只有 netpack 原始 `coords` + `from/to` + `direction` | 证"仓库里的真网数据本身是什么口径"；可 `git diff`，任何人可复算；**不证**运行时 |
| **L3 图纸 + 截图 + 离站对照**（`direction_sheet.svg`、`shots/**`、`departure_check.json`） | 图纸：由 L2 数据独立画灰线(coords 序)与彩线(行进序)；截图：在**真实浏览器**里读 `map.project()`、`queryRenderedFeatures()`、`icon-rotate` 表达式的**求值结果**；离站对照：用 `steps[].geometry` 的行进方位与静态层 `rotate` 逐度比 | 真实前端 + 真实 MapLibre 渲染 + 真实后端 `/steps` | 证"用户屏幕上那支箭头在哪、朝哪"；**不证**后端自检内部逻辑 |

**交叉链（三处独立收敛）**：

1. **L2 ↔ 后端 `steps[].geometry`**：netpack 反推的方位角与 `steps[].geometry` 相邻点方位差 **0.000°**（16 步全量）——
   说明后端行进序几何就是从同一份 netpack 按正确顺序取的，没有偷偷重排。
2. **L2 ↔ L3 截图**：截图里 61 个方向要素的分类（14/14/33）与 L2 快照逐类相等；箭头中心与"用 L2 `coords` 独立算的弧长中点"
   差 ≤0.068 px —— 前端没有用自己的顺序重新解释几何。
3. **L1 ↔ L3-e**：L1 断言 `start_point == coords[0]`（reverse 段不镜像）与 L3-e 实测"端点标记 == 行进序端点（0.000 m）"
   是同一件事的两端（后端算的对 / 前端标的对）。

> ⚠️ **措辞澄清（别把这条读成"业主报错了"）**：业主报的"起点标在 `SZ-004` 段末尾"**是真事、也确实在现场看得见**，但错的地方不是标记坐标，而是**那条路线本身从段的另一端起头**。
> 精确链条：真值 `SZ-004` 是 `reverse` 段、`offset_m` 是 **coords 序**弧长；旧 `route_service._start_from()` 把这个 `offset_m` 当**行进序**读 ⇒ 引擎认为车在 `N-040`、整段当成未走过的前缀 ⇒ 画出来的线从 `N-040` 起头；而前端 `pointAtOffset(coords, offset_m)` 按 coords 序插值**一直是对的**，把标记画在 `N-022`（车真正所在处）——于是"对的点"落到了"错的线的尾巴上"，业主看到的就是"起点标在段末尾"。两处相距 **120.7 m = 整段长度**（`work/verify/README.md:121` 同一结论）。
> 三个源的结论是：**标记口径没错、后端方向语义没错，错的是"引擎把 coords 序里程当行进序"这一处**（已在 `work/engine/route_service.py:133-142` / `:561-598` 修掉，并加了 H 组断言看守）。

   **不能**当"底图观感"证据（业主问"地图为什么空白"时，答案是瓦片离线，与箭头标向无关）。
6. **双向段的静态层方向不可视证**：双头箭头两头都有锥尖（`MapLibreViewer.vue:698-745` `paintArrowGlyph(..., double=true)`），画反也看不出来；

   就是用户可见的**指反**；这正是路线箭头改为吃 `steps[].geometry` 的动因。
