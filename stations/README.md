# stations · 站点包

> **目标**：**换一个高铁站只改配置、不改引擎代码。**
>
> 所有站点相关的内容都放在这里。**引擎代码里不得出现任何站点名、坐标、路名硬编码。**

## 六个文件

| 文件 | 内容 | 谁填 |
|---|---|---|
| `network.json` | 路网拓扑：节点 / 边 / 属性（车道数、限速、通行能力） | 决策线定结构，数据与标注岗填 |
| `points.json` | 点位标签：落客点 / 上客点 / 候客区 / 检测断面 / 路口 | 数据与标注岗（**人工打标签**） |
| `calibration.json` | 每个摄像头的单应矩阵、控制点、有效标定带 | 感知线 + 数据与标注岗 |
| `signal_plan.json` | 信号配时（demo：1 个路口、2 套方案：平峰 / 高峰） | 数据与标注岗 |
| `scenarios.json` | 情景参数（时段 / 日历 / 天气系数、OD 需求矩阵） | 决策线 |
| `thresholds.json` | 判级阈值与权重 | 感知线（**换站必须重新标定**） |

## 点位标签怎么打

**候客区等点位由人在真实地图底图上人工打标签确认，不等官方口径。**

底图来自**高德地图 / 百度地图开放平台 API**（真实地图数据）。一期是「**真实底图 + 虚拟车流**」。

要打的五类标签：

| 标签类型 | 圈什么 | 必填属性 |
|---|---|---|
| 落客点 | 门口落客区 / 路边临停段 / 停车场落客位 | 类型（服务率型）、允许停留时长、服务率 |
| 上客点 | 门口即走上客位 | 类型（服务率型）、允许停留时长 |
| 候客区 / 蓄车区 | 出租车专属 / 网约车专属 / 社会车辆 | 类型（车位数型）、车位数、进出规则 |
| 检测断面 | 每条待测路段的虚拟断面线 | 桩号、车道数、对应视频文件 |
| 平交路口 | 影响车流的上游与站前路口 | 是否有信号、配时方案编号 |

**拿不到官方数据时**按现场照片 / 公开地图估算，**逐项标「待核实」**；二期实地考察时逐条订正。

## 坐标系（**这一步错了，后面全错**）

三套坐标系并存，必须显式转换：

| 坐标系 | 谁在用 |
|---|---|
| **WGS-84** | GPS / 北斗原始输出、卫星定位 |
| **GCJ-02** | 高德地图 |
| **BD-09** | 百度地图 |

**硬规则**：
1. **站点包统一存 WGS-84**，并在字段里标注原始坐标系；
2. 与高德交互：WGS-84 ↔ GCJ-02；与百度交互：WGS-84 ↔ BD-09（经 GCJ-02 中转）；
3. **定位数据进入系统前先转成 WGS-84**，否则司机位置和路网对不上，推荐路线会整体偏移几十到几百米；
4. 转换算法**离线内置**；
5. 验收项：同一地点三种坐标系各取一次，转换后两两误差 ≤ 5 m。

## 换一个站要改什么、不改什么

| 要改 | 不改 |
|---|---|
| `network.json`（路网） | 引擎代码 |
| `points.json`（点位标签） | 判级算法 |
| `calibration.json`（标定） | 配额租约机制 |
| `signal_plan.json`（配时） | 接口契约 |
| `thresholds.json`（阈值，**必须重新标定**） | 前端页面结构 |
| `scenarios.json`（需求与情景） | 数据字段定义 |

**判定标准**：换一个站只新增 / 替换配置文件即可接入，**不改引擎代码**。

## 什么能进仓库

- **能进**：上面六个 JSON（小文本）、点位清单、标定参数表；
- **不能进**：地图瓦片、拉取的原始矢量数据、图片数据集 —— 放共享盘。
