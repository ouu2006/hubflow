# stations · 站点包

> **目标**：**换一个高铁站只改配置、不改引擎代码。**
>
> 所有站点相关的内容都放在这里。**引擎代码里不得出现任何站点名、坐标、路名硬编码。**
>
> **谁填**：结构由**开发A / 开发B** 定；数据由 **N1（地图与站点员）/ N2（场景与因素员）** 填表格（他们也参与部分技术开发：补画路网、拾取控制点、配置因素与场景），开发写的转换脚本把表格转成这里的 JSON。

## 文件清单

| 文件 | 内容 | 谁填 |
|---|---|---|
| `network.json` | 路网拓扑：节点 / 边 / 属性（车道数、限速、通行能力）。**由 OSM + `netconvert` 生成**，再按 T2 路段属性核对表补录 | **结构：开发B**；**数据：N1**（T2 核对补录） |
| `points.json` | 点位标签：落客点 / 上客点 / 候客区 / 平交路口 / **检测断面** | **N1**（T1 点位表，人工打标签） |
| `signal_plan.json` | 信号配时（demo：1 个路口、2 套方案：平峰 / 高峰） | **N1**（按底图与现场核对后手填） |
| `demand.json` | **新**：列车时刻 + OD 需求 + 车型 / 司机类型比例 | **N2**（T3 列车时刻表 / T4 需求比例表） |
| `factors.json` | **新**：因素登记与时间窗（F01~F14，14 类因素） | **N2**（T5 因素表） |
| `scenarios.json` | 场景：四个演示场景的开关、注入事件、随机种子 | **N2 + N4**（T6 场景剧本表） |
| `thresholds.json` | 判级阈值与权重（一期 demo 值；二期**按路段**重标定） | **开发A**（**换站必须重新标定**） |
| `calibration.json` | **【二期】**摄像头标定：单应矩阵、控制点、有效标定带 | **开发A**（二期现场标定） |
| `sumo/` | `netconvert` 产出的 `.net.xml` 等**小文本** | **开发A**（**由脚本生成、可重建**，见下） |
| `map_source.json` | 溯源记录：provider / 拉取时间 / 坐标系 / 缺失字段清单 | **开发B**（`map_ingest.py` 产出） |

> **表格 → 配置的对应关系**见 [`../docs/分工表.md`](../docs/分工表.md) 与 [`../docs/表格模板说明.md`](../docs/表格模板说明.md)：T1 点位表 → `points.json`、T2 路段属性核对表 → `network.json`、T3/T4 → `demand.json`、T5 → `factors.json`、T6 → `scenarios.json`。**转换脚本由开发写，N1 / N2 只填表格。**

### `sumo/`（脚本生成，可重建）

- **内容**：`netconvert` 从站点 OSM 转出的 `.net.xml`，以及 `netedit` 手工补画后的修订版；都是**小文本**，可以进仓库；
- **口径**：**由脚本生成、可重建**。生成命令写在 [`../work/twin/README.md`](../work/twin/README.md)，**不要把 `netconvert` 的中间产物（`.poly.xml`、日志）当源码提交**；
- **不许手改生成物**：要改路网，改**输入（OSM 切片 / 补画记录）**或**转换参数**，然后重跑脚本——手改 `.net.xml` 会在下次重建时丢失。

### `map_source.json`（溯源记录，**引擎不读**）

> 由 `map_ingest.py` 产出，记录 provider、拉取时间、坐标系、缺失字段清单。
> **引擎不读它**，它只用于复核"**这个站的路网是哪天从哪家拉的、哪些字段是人工补的**"——地图 API 的数据质量必须能追溯（TC-15 路网核对要用）。
>
> **一期口径**：路网拓扑走 **OSM + netconvert**；高德 / 百度开放平台**只用于底图核对与管理端渲染**，**不用它提取车道级路网拓扑**。

## 点位标签怎么打

**候客区等点位由人在真实地图底图上人工打标签确认，不等官方口径。**

底图来自**高德地图 / 百度地图开放平台 API**（真实地图数据）。一期是「**真实底图 + 虚拟车流**」。

要打的五类标签：

| 标签类型 | 圈什么 | 必填属性 |
|---|---|---|
| 落客点 | 门口落客区 / 路边临停段 / 停车场落客位 | 类型（服务率型）、允许停留时长、服务率 |
| 上客点 | 门口即走上客位 | 类型（服务率型）、允许停留时长 |
| 候客区 / 蓄车区 | 出租车专属 / 网约车专属 / 社会车辆 | 类型（车位数型）、车位数、进出规则 |
| **检测断面** | 每条待测路段的检测断面线 | 桩号、车道数、**一期虚拟检测器编号 / 二期摄像头编号**、对应视频文件（二期） |
| 平交路口 | 影响车流的上游与站前路口 | 是否有信号、配时方案编号 |

> **检测断面点位口径（一期与二期必须同点位）**：`points.json` 里的 `detector` 类点位就是检测断面——**一期放虚拟检测器、二期放真摄像头**，位置一一对应。
> 这是 D1「二期换数据源、不改下游」能成立的前提：字段与点位都提前定成二期形状。**N1 打点位时要按"将来摄像头装在哪"来打，不要按"一期方便在哪测"来打。**

**拿不到官方数据时**按现场照片 / 公开地图估算，**逐项标「待核实」**；二期实地考察时逐条订正（TC-15 路网核对表）。

## 坐标系（**这一步错了，后面全错**）

三套坐标系并存，必须显式转换：

| 坐标系 | 谁在用 |
|---|---|
| **WGS-84** | GPS / 北斗原始输出、卫星定位、**站点包统一存储格式** |
| **GCJ-02** | 高德地图 |
| **BD-09** | 百度地图 |

**硬规则**：

1. **站点包统一存 WGS-84**，并在字段里标注原始坐标系；
2. 与高德交互：WGS-84 ↔ GCJ-02；与百度交互：WGS-84 ↔ BD-09（经 GCJ-02 中转）；
3. **定位数据进入系统前先转成 WGS-84**，否则司机位置和路网对不上，推荐路线会整体偏移几十到几百米；
4. 转换算法**离线内置**，不要每次调在线接口；
5. 验收项：同一地点三种坐标系各取一次，转换后两两误差 ≤ 5 m。

> **两期都一样**：一期孪生内部用米制坐标（可换算 WGS-84），二期 App 上报的北斗 / GNSS 是 WGS-84；**统一口径不变**。

## 换一个站要改什么、不改什么

| 要改 | 不改 |
|---|---|
| `network.json`（路网） | 引擎代码 |
| `points.json`（点位标签） | 判级算法 |
| `signal_plan.json`（配时） | 时段预约与不伤害约束机制 |
| `demand.json`（列车时刻 / OD 需求） | 接口契约 |
| `factors.json`（因素登记） | 前端页面结构 |
| `scenarios.json`（场景与种子） | 数据字段定义 |
| `thresholds.json`（阈值，**必须重新标定**） | — |
| `sumo/`（重跑 `netconvert` 重建） | — |
| `calibration.json`（**二期**，摄像头标定） | — |

**判定标准**：换一个站只新增 / 替换配置文件（+ 重跑路网转换脚本）即可接入，**不改引擎代码**。

## 什么能进仓库

- **能进**：上面清单里的 JSON（小文本）、`sumo/` 下的 `.net.xml`（小文本、可重建）、点位清单、标定参数表（二期）；
- **不能进**：地图瓦片、拉取的原始矢量数据、OSM 原始大文件、图片数据集、视频 —— 放共享盘。
