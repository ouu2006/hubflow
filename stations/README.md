# stations · 站点包

> **目标**：**换一个高铁站只改配置、不改引擎代码。**
>
> 所有站点相关的内容都放在这里。**引擎代码里不得出现任何站点名、坐标、路名硬编码。**
>
> **谁填**：**结构由开发B 定**（[`../docs/开发规范.md`](../docs/开发规范.md) 第 3.1 节、[`../docs/数据契约.md`](../docs/数据契约.md) 第六节）；数据由**协作成员按任务池认领**填表格——按系列落到 **池·S**（站点 / 踏勘：T1 点位表、T2 路段属性核对表、T3 列车时刻表、T4 需求比例表、T6 场景剧本表）与 **池·P**（参数 / 调研：T5 因素表），协作成员也参与部分技术开发（补画路网、拾取控制点、配置因素与场景）；开发写的转换脚本把表格转成这里的 JSON。**`sumo/*.net.xml` 由开发A 的路网脚本产出**（开发B 不重跑 `netconvert`）；**`thresholds.json` 不是例外——判级参数组 + 决策参数组都只有开发B 一个写手**。
>
> **角色简称**：开发A / 开发B / 开发C；**池·V / 池·S / 池·P / 池·Q** = 任务池四个系列（视频线 / 站点踏勘 / 参数调研 / 独立验收）的**认领者**（协作成员，无锁角色，原 N1~N4 定岗已作废）；**队长** = 7 人中 1 人兼任，**不参与认领**。

## 文件清单

| 文件 | 内容 | 谁填 |
|---|---|---|
| `network.json` | 路网拓扑：节点 / 边 / 属性（车道数、限速、通行能力）。**统一图结构，由开发B 的 `map_ingest.py` 从 OSM + `netconvert` 产物生成**，再按 T2 路段属性核对表补录 | **产出：开发B**（`map_ingest.py`）；**数据：池·S**（T2 核对补录） |
| `points.json` | 点位标签：落客点 / 上客点 / 候客区 / 平交路口 / **检测断面**（检测断面**必填 `role`（`boundary` / `internal`）与 `sumo_edge_id`**；**只有 `boundary` 才允许数据同化回灌**） | **结构：开发B**（T1 转换脚本）；**数据：池·S**（T1 点位表，人工打标签） |
| `signal_plan.json` | 信号配时（demo：1 个路口、2 套方案：平峰 / 高峰） | **结构：开发B**；**数据：池·S**（按底图与现场核对后手填） |
| `demand.json` | **新**：列车时刻 + OD 需求 + 车型 / 司机类型比例 | **结构 / 脚本：开发A**；**数据：池·S**（T3 列车时刻表 / T4 需求比例表） |
| `factors.json` | **新**：因素登记与时间窗（F01~F14，14 类因素） | **结构 / 脚本：开发A**；**数据：池·P**（T5 因素表） |
| `scenarios.json` | 场景：四个演示场景的开关、注入事件、随机种子、**`assimilation`（数据同化开关，**结构由开发B 定**，见下）** | **结构：开发B**（W0 定 `assimilation` 字段）；**脚本：开发A**；**数据：池·S**（T6 场景剧本表） |
| `thresholds.json` | 判级阈值与权重（一期 demo 值；二期**按路段**重标定）。**文件内分两组**：**判级参数**（等级边界 / 权重 / `v_f` / 因素合成下限）与**决策参数**（BPR `alpha` / `beta`、`x_safe`、`eps_harm_s`、`k_candidates`、`hysteresis`、`lease_expire_s`）。**两组顶层键名由开发B 在 W0 定结构时定**（见 [`../docs/数据契约.md`](../docs/数据契约.md) 第六节） | **唯一写手：开发B**（判级参数组 + 决策参数组，见下方 ⚠️） |
| `calibration.json` | **一期（样本视频标定）/ 二期（现场摄像头标定）**：单应矩阵、控制点、有效标定带。**视频链路的输出标 `source: "video"`**（二期换现场实时流后**不变**） | **控制点由池·V 拾取**（≥4 组，推荐 6–8 组）；**开发A** 求解单应矩阵并写文件（二期现场重做；`source` **仍是 `"video"`**，字段不变） |
| `sumo/` | `netconvert` 产出的 `.net.xml` 等**小文本** | **开发A**（**由脚本生成、可重建**，见下） |
| `map_source.json` | 溯源记录：provider / 拉取时间 / 坐标系 / 缺失字段清单 | **开发B**（`map_ingest.py` 产出） |

> ⚠️ **`network.json` 与 `sumo/` 是两个不同的人产出的两个东西，别互相覆盖**：
> · **`stations/sumo/*.net.xml`** = SUMO 路网，**开发A** 用 `netbuild.py`（`netconvert`）+ `netedit` 补画产出；
> · **`stations/network.json`** = 引擎读的**统一图结构**（`{nodes, edges, attributes}`），**开发B** 用 `map_ingest.py` 从 OSM 与上述 `.net.xml` 生成。
> 开发A 需要图结构时**读** `network.json`，**不写**它；开发B **不重跑** `netconvert`、不写 `sumo/`。详见 [`../work/engine/README.md`](../work/engine/README.md) 第五节与手册第 8.3 节。
>
> ⚠️ **`thresholds.json` 只有一个写手：开发B**——**判级参数组与决策参数组都归开发B**（含两组顶层键名），**判级 `level.py` 也归开发B**（[`../docs/开发规范.md`](../docs/开发规范.md) 第 3 / 3.1 节、[`../docs/数据契约.md`](../docs/数据契约.md) 第六节）。**全仓"一个文件只许一个写手"，没有例外**：开发A 既不碰 `level.py`，也不碰本文件的任何一组参数。

> **表格 → 配置的对应关系**见 [`../docs/分工表.md`](../docs/分工表.md) 与 [`../docs/表格模板说明.md`](../docs/表格模板说明.md)：T1 点位表 → `points.json`、T2 路段属性核对表 → `network.json`、T3/T4 → `demand.json`、T5 → `factors.json`、T6 → `scenarios.json`。**转换脚本由开发写，池·S / 池·P 只填表格；任务由区域 owner 拆活后在 GitHub Issues 发布、协作成员认领（只发布、不点名；细则见 [`../docs/hubflow-plan/04-协作任务池规程.md`](../docs/hubflow-plan/04-协作任务池规程.md)）。**

### `sumo/`（脚本生成，可重建）

- **内容**：`netconvert` 从站点 OSM 转出的 `.net.xml`，以及 `netedit` 手工补画后的修订版；都是**小文本**，可以进仓库；
- **口径**：**由脚本生成、可重建**。生成命令写在 [`../work/twin/README.md`](../work/twin/README.md)，**不要把 `netconvert` 的中间产物（`.poly.xml`、日志）当源码提交**；
- **不许手改生成物**：要改路网，改**输入（OSM 切片 / 补画记录）**或**转换参数**，然后重跑脚本——手改 `.net.xml` 会在下次重建时丢失。

### `map_source.json`（溯源记录，**引擎不读**）

> 由 `map_ingest.py` 产出，记录 provider、拉取时间、坐标系、缺失字段清单。
> **引擎不读它**，它只用于复核"**这个站的路网是哪天从哪家拉的、哪些字段是人工补的**"——地图 API 的数据质量必须能追溯（TC-15 路网核对要用）。
>
> **一期口径**：路网拓扑走 **OSM + netconvert**；高德 / 百度开放平台**只用于底图核对与管理端渲染**，**不用它提取车道级路网拓扑**。

## 点位标签怎么打

**候客区等点位由人在真实地图底图上人工打标签确认，不等官方口径。**

底图来自**高德地图 / 百度地图开放平台 API**（真实地图数据）。一期是「**真实底图 + 虚拟车流**」。

要打的五类标签：

| 标签类型 | 圈什么 | 必填属性 |
|---|---|---|
| 落客点 | 门口落客区 / 路边临停段 / 停车场落客位 | 类型（服务率型）、允许停留时长、服务率 |
| 上客点 | 门口即走上客位 | 类型（服务率型）、允许停留时长 |
| 候客区 / 蓄车区 | 出租车专属 / 网约车专属 / 社会车辆 | 类型（车位数型）、车位数、进出规则 |
| **检测断面** | 每条待测路段的检测断面线 | 桩号、车道数、**一期虚拟检测器编号 / 二期摄像头编号**、**对应视频文件（一期：6 段真实样本视频；二期：现场实时流）**、**角色（`boundary` / `internal`）**、**对应 SUMO edge id（`sumo_edge_id`）** |
| 平交路口 | 影响车流的上游与站前路口 | 是否有信号、配时方案编号 |

> **检测断面点位口径（一期与二期必须同点位）**：`points.json` 里的 `detector` 类点位就是检测断面——**一期放虚拟检测器（孪生链路）、二期放真摄像头**，位置一一对应；**视频感知链路**（一期跑 6 段真实样本视频、二期接现场实时流）**用的是同一批断面点位**。
> 这是 D1′「二期换数据源、不改下游」能成立的前提：字段与点位都提前定成二期形状。**池·S 打点位时要按"将来摄像头装在哪"来打，不要按"一期方便在哪测"来打**；**并按 T1 一并拾取视频链路的透视标定控制点（这一项属系列 V，由池·V 认领）**。
>
> **检测断面的两个必填新属性（数据同化的前提，见 [`../docs/数据契约.md`](../docs/数据契约.md) 第 6.1 节）**：
> ① **角色 `role`**——**`boundary`** = 围栏外 → 站前的**上游边界断面**；**`internal`** = **站前内部路段**（落客通道 / 候客区 / 离站方向）的断面。**必填，只能取这两个值**；
> ② **`sumo_edge_id`**——该断面**对应的 SUMO edge id**（`sumo/*.net.xml` 里的边编号）。**必填**；SUMO 的 `<calibrator>` 就挂在这条边上，**映射错了就灌到别的路上**。
>
> ⚠️ **只有 `boundary` 会被数据同化回灌**：视频链路的实测流量 / 车速每 **60 s** 通过 `calibrator` 回灌给孪生的**边界来车**；**`internal` 断面一个都不许挂 `calibrator`**——否则孪生变成"录像回放"、推荐再也改变不了路况，"同一输入跑三遍只切推荐"的对照实验直接失效（**TC-20 第②项**专验）。一期至少 **1 个边界断面**（**M1-10**），二期全部边界断面在线闭环 + 熔断（**M2-9**）。
>
> **边界断面清单由池·S 填、开发A / 开发B 核对、队长签字冻结**（冻结后要改走变更流程）。

**拿不到官方数据时**按现场照片 / 公开地图估算，**逐项标「待核实」**；二期实地考察时逐条订正（TC-15 路网核对表）。

## 坐标系（**这一步错了，后面全错**）

三套坐标系并存，必须显式转换：

| 坐标系 | 谁在用 |
|---|---|
| **WGS-84** | GPS / 北斗原始输出、卫星定位、**站点包统一存储格式** |
| **GCJ-02** | 高德地图 |
| **BD-09** | 百度地图 |

**硬规则**：

1. **站点包统一存 WGS-84**，并在字段里标注原始坐标系；
2. 与高德交互：WGS-84 ↔ GCJ-02；与百度交互：WGS-84 ↔ BD-09（经 GCJ-02 中转）；
3. **定位数据进入系统前先转成 WGS-84**，否则司机位置和路网对不上，推荐路线会整体偏移几十到几百米；
4. 转换算法**离线内置**，不要每次调在线接口；
5. 验收项：同一地点三种坐标系各取一次，转换后两两误差 ≤ 5 m。

> **两期都一样**：一期孪生内部用米制坐标（可换算 WGS-84），二期 App 上报的北斗 / GNSS 是 WGS-84；**统一口径不变**。

## 换一个站要改什么、不改什么

| 要改 | 不改 |
|---|---|
| `network.json`（路网） | 引擎代码 |
| `points.json`（点位标签；**检测断面的 `role` / `sumo_edge_id` 是数据同化的映射**） | 判级算法 |
| `signal_plan.json`（配时） | 时段预约与不伤害约束机制 |
| `demand.json`（列车时刻 / OD 需求） | 接口契约 |
| `factors.json`（因素登记） | 前端页面结构 |
| `scenarios.json`（场景与种子；**`assimilation` 数据同化开关**） | 数据字段定义 |
| `thresholds.json`（阈值，**必须重新标定**） | — |
| `sumo/`（重跑 `netconvert` 重建） | — |
| `calibration.json`（**一期样本视频标定 / 二期现场摄像头标定**） | — |

> **数据同化不新增站点包文件**：**开关在 `scenarios.json`（`assimilation`），断面 ↔ edge 映射在 `points.json`（`role` / `sumo_edge_id`）**——换站时这两处跟着站点包一起换，引擎代码不改。

**判定标准**：换一个站只新增 / 替换配置文件（+ 重跑路网转换脚本）即可接入，**不改引擎代码**。

## 什么能进仓库

- **能进**：上面清单里的 JSON（小文本）、`sumo/` 下的 `.net.xml`（小文本、可重建）、点位清单、**标定参数表（一期：样本视频标定；二期：现场标定）**；
- **不能进**：地图瓦片、拉取的原始矢量数据、OSM 原始大文件、图片数据集、视频 —— 放共享盘。
